仕組み

DetergentMC は、Mojang のバニラサーバーを子プロセスとして動かし、その前にプロキシを置く構成です。ワールドやティックはバニラそのものが担当し、DetergentMC の層がバージョン間の違いを吸収します。

3つのポート

プロキシ — 25565

プレイヤーが接続する入口です。クライアントのバージョンを見て、対応するアダプターに振り分けます。

バージョン間アダプター（759〜775）

内部バニラ — 25566

Mojang のバニラサーバーを子プロセスとして動かします。ワールド生成・チャンク・ティックはすべてバニラの仕事です。

Mojang バニラサーバー（Java）

リソースパック — 25567

バージョン別のリソースパックを配信します。古いクライアントでも新しいブロックや UI を見せるための土台です。

バージョン別パック 17 個

設定は detergentmc.yml に書きます。公開用のリソースパック配信場所はまだ決めていないため、開発段階ではループバック配信（127.0.0.1:25567）を使っています。

バージョン間アダプター

クライアントとサーバーのバージョンが違っても、プロキシがパケットとレジストリを翻訳してつなぎます。新しいバージョン向けのプラグインを古いバージョンでも使えるようにするのが、この仕組みの目的です。

  • パケット ID の翻訳：バージョンごとに異なるパケット番号を対応表で変換します。
  • レジストリの翻訳：ブロック状態・アイテム・音・エンティティなどの対応表をバージョンごとに持ちます。1.20.4 だけでもブロック状態は 26,644 件あります。
  • 設定フェーズの合成：1.19 系には設定フェーズがないため、プロキシが 1.20 系と同じ流れを合成します。
  • チャット署名：署名付きチャットは 1.19（759）で導入され、1.19.1（760）で形式が変わりました。バージョンをまたぐ署名チェーンは未対応です。

Bedrock 対応

Bedrock Edition のクライアントも、同じプロキシで受け付けます。UDP 19132 番で待ち受け、RakNet プロトコル 30 個に対応しています。

  • チャンクの翻訳：Java のブロック状態を Bedrock のランタイム ID に変換します。バイオームも変換します。
  • エンティティの翻訳：Java のエンティティ 126 種を Bedrock へ写します。出現・移動・向き・装備・エフェクト・乗騎などに対応します。
  • 制限：インベントリは未対応です。Xbox 署名の検証や暗号化はまだなく、NACK による再送もありません。最新の Bedrock 26.60 / 26.62 には未対応です。

正直な話

  • 本物のゲームクライアントでの確認は、まだどの組み合わせも行っていません。検証はプロトコルレベル（偽クライアントと本物のバニラサーバー）です。
  • 変換できないものもあります。一部のパケットやデータは、変換できない場合に落としたり中立的な値に置き換えたりします。詳しくはリポジトリのドキュメントをご覧ください。
