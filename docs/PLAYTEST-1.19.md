## 0. この手順書の読み方：プロトコル検証済み／実機でしか確認できないもの

DetergentMCの1.19対応は、ここに書く項目の多くを**プロトコルレベルでは
すでに検証済み**である（本物のバニラ子プロセス＋生ソケットで759クライアントを
装った統合テスト `ProxyIntegrationTest`、`ChunkTranslator759Test`、
`PlayTranslator759Test` など）。実機テストの目的は、プロトコルレベルでは
見えない「本物のゲームクライアントでの見た目・挙動」を確かめることである。
以下の2つに分けて読むこと。

### A. プロトコルレベルで既に検証済みの項目（実機では「同じことが起きるか」の確認）

- 759クライアントの1.19サーバー（内部759）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla119ThroughProxy`）。
  素通し（リレー）。Join Game の codec に dimension_type と biome が含まれることを確認
- 759クライアントの1.19.1サーバー（内部760）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla1191ThroughProxy`）。
  759→760の直接変換（パケットID 131件変更、Player Chat の初代インライン署名形式、
  System Chat の type varint、Server Data の enforcesSecureChat、Trade List の u8 カウント、
  Login Start の UUID 欄なし）。chat_suggestions／hide_message／message_header を落とす
- 759クライアントの1.19.2サーバー（内部760）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla1192ThroughProxy`）。
  1.19.1と同じプロトコル760のため同じ流れ
- 759クライアントの1.19.3サーバー（内部761）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla1193ThroughProxy`）。
  759→760→761の合成変換。ログイン成功のあと両方ともすぐプレイ状態へ進む。
  Join Game は0x23のまま
- 759クライアントの1.19.4サーバー（内部762）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla1194ThroughProxy`）。
  759→760→761→762の合成変換
- 759クライアントの1.20.1サーバー（内部763）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake759ClientJoinsRealVanilla1201ThroughProxy`）。
  759→760→761→762→763の合成変換。Join Game の portalCooldown を落として送る
- 760クライアントの1.19サーバー（内部759）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake760ClientJoinsRealVanilla119ThroughProxy`）。
  760→759の逆向き変換。Login Start からUUID欄を落とす
- 本物の1.19の Join Game codec の中身：chat_type・dimension_type・worldgen/biome の3レジストリだけ。
  **minecraft:damage_type レジストリは無い**（1.19.4で追加）。
  バイオーム63件・plains=1・cherry_grove 無し
- 759↔760のレジストリ差分（ViaVersion `mapping-1.19.json` と minecraft-data で確認）：
  パケットID 131件変更、ブロック状態 21,448件・同じ、アイテム 1,152件・同じ、
  エンティティ 118件・同じ（player は759=116、760=116）、音 1,321件・同じ、
  パーティクル 93件・同じ、エンチャント 39件・同じ、
  エフェクト 33件・同じ、バイオーム 63件・同じ顔ぶれ・同じ並び（plains は759=1、760=1）、
  ダメージ種別は759に存在しない、メニュー 24件・同じ、
  ブロックエンティティ種別 36件・同じ、絵画 30件・同じ、楽器 23件・同じ、属性 13件・同じ
- 759用リソースパック（pack_format 9）の生成と配信
  （`ResourcePackBuilder759Test`、`ResourcePackServer759Test`）
- `/trigger d_hello` / `d_lang_ja` / `d_lang_en` の動作（言語切替と保存を含む。
  759クライアントでも同じ。直接 `/hello` と打っても動かない。`/trigger d_hello` を使うこと）

### B. 実機でしか確認できない項目（この手順書の中心）

- 本物の1.19クライアントが、1.19.1／1.19.2サーバーの Join Game codec を無視して参加できるか
  （759と760の codec は同じ3レジストリのため、素通しのはず）
- 本物の1.19クライアントが、1.19.3サーバーの Join Game codec
  （bamboo 入りのブロック一覧）を無視して参加できるか
- 本物の1.19クライアントが、1.20.1／1.21.11サーバーの Join Game codec
  （trim の追加フィールド、damage_type の `effects`、cherry_grove 入りの
  バイオーム一覧）を無視して参加できるか
- 1.19.3サーバー側の新しいブロック（bamboo 系、hanging sign、chiseled_bookshelf、
  piglin_head、stripped_bamboo_block）が1.19クライアントに
  どう見えるか（代替：oak 系、同じ木の sign、bookshelf、zombie_head）
- 1.19.3サーバー側の新しいアイテム（bamboo 系、bamboo_raft／chest_raft、
  hanging sign、camel_spawn_egg、ender_dragon／iron_golem／snow_golem／
  wither_spawn_egg、piglin_head）が1.19クライアントにどう見えるか
  （代替：oak 系、oak_boat／oak_chest_boat、horse_spawn_egg、dragon_egg、
  iron_ingot、snowball、nether_star、zombie_head）
- 1.19.3サーバー側の新しいエンティティ（camel）が
  1.19クライアントにどう見えるか（代替：馬）
- 1.19.3サーバー側の新しい音（bamboo_wood 系、camel 系、chiseled_bookshelf、
  hanging_sign、nether_wood、note_block の新楽器）が1.19クライアントで
  どう聞こえるか（代替：木の音、馬の声、harp）
- 1.19.3サーバーの chiseled_bookshelf・hanging_sign の中身（ブロックエンティティ）が
  1.19クライアントでどう見えるか（ブロックエンティティは落とすため、中身は表示されないはず）
- **チャットの署名チェーン**：760以上のサーバーからのチャットが、実機の
  1.19クライアントで未検証（署名なし）と表示されるかどうか。
  プロキシは759→760で previousMessages を空にし、Message Header を合成しない。
  チャットが表示されるか、警告が出るか、表示されないかを確かめること。
  逆に、実機の1.19.1クライアントが1.19サーバーからのチャットをどう表示するかも確かめること
- **Multi Block Change の bool の意味**：759は `notTrustEdges`、760は `suppressLightUpdates`。
  プロキシは同じ位置の1バイトとしてそのまま通している。チャンクの更新で
  見た目のおかしな点が無いか確かめること
- 1.19クライアントに759用パック（pack_format 9）が提示され、適用されるか
- **2人同時参加（他プレイヤーの出現・スキン・チャット）**。`named_entity_spawn`（0x02）を
  実バニラ1.19が送るかどうかは未確認。偽クライアントでは、直接接続でも
  プロキシ経由でも、他プレイヤーの出現パケットが30秒以内に届かなかった
  （1.19.3・1.19.1と同じ）。
  **実機クライアントで2人同時に遊び、相手が見えるかどうかを確かめるのが
  最も重要な残りの検証である**。相手が見えない場合は、ログの文言と一緒に報告すること。
  また、759クライアントが Spawn Entity（player種別）を受け入れるかどうかも
  ここで確かめる（プロキシは759＋759では素通しのため、1.19サーバーが
  Spawn Entity を送ってきた場合、そのままクライアントに届く）
- 764以上のクライアント（1.20.2以降）が759サーバーに参加したとき、
  damage_type レジストリ無しの合成設定フェーズを受け入れるか

## 1. 起動

### 1.1 準備（初回のみ）

```sh
cd ~/workspace/detergentmc
./gradlew build :bubbles:hello-bubble:jar
cp bubbles/hello-bubble/build/libs/hello-bubble-0.1.0-1.20.4.jar run/bubbles/
```

`run/eula.txt` と `run/vanilla/eula.txt` が `eula=true` になっていること。

### 1.2 起動（ファットjar・推奨）

```sh
cd ~/workspace/detergentmc
JAVA_HOME=/home/hatch/workspace/.tools/jdk-17.0.21+9 \
  java -jar build/libs/detergentmc-0.1.0-1.20.4.jar
```

`detergentmc.yml` の `minecraft-version` を `1.19` にして起動すると、
内部759サーバーが Java 17 で起動する。`1.19.1` にすると内部760サーバー、
`1.19.2` にしても同じ内部760サーバー、`1.19.3` にすると内部761サーバー、
`1.19.4` にすると内部762サーバー、`1.20.1` にすると内部763サーバーになる（切り替えて試すこと）。

### 1.3 接続（実機クライアント）

Minecraft Java Edition 1.19 のクライアントで `127.0.0.1:25565` に接続する。
オフラインモード（`online-mode: false`）の場合は、ランチャーのプロファイルで
オフラインモードを有効にするか、適当な名前で接続すること。

## 2. チェックリスト（1.19クライアント → 内部759サーバー）

- [ ] 参加できる（切断されない）。スポーン地点に立つ
- [ ] 地面・木・水などの見た目が正しい（ブロック状態の変換が正しい）
- [ ] 移動できる（歩く・走る・泳ぐ・ジャンプ）

- [ ] `/trigger d_lang_en` で英語に切り替わる。`/trigger d_lang_ja` で日本語に戻る
- [ ] リソースパックが提示される（pack_format 9）。適用される
- [ ] インベントリを開ける。アイテムを動かせる（Window Click の変換）
- [ ] クリエイティブでアイテムを取れる（Set Creative Slot の変換）
- [ ] 看板を立てて文字を書ける（Update Sign の変換）
- [ ] 死んでリスポーンできる（Respawn の変換）
- [ ] 村人と取引できる（Trade List の変換。u8⇔varint）
- [ ] 2人目が参加したとき、相手が見える（Player Info・出現パケット）。
  **ここが最重要の未確認項目**。相手が見えない・相手が馬に見える・
  姿がおかしい場合は、そのままの様子を報告すること
