# プロトコル61（Minecraft 1.5.2）— Netty 以前世代フロントエンド

DetergentMC の Netty 以前世代フロントエンド（モジュール
`detergentmc-legacy-frontend`、docs/PROXY-1.6.4.md）の第4弾。
レガシープロトコル 61（1.5.2）を 78／74／73 と同じ基盤に追加する。
世代が 1.6 から 1.5 へ下るため、差分は 74⇔73（2件）より大きい。

**状態：Stage E 完了（2026-11-20）。** 74／73 の Stage E
最終 HEAD（`efaefbb`）へリベースし（競合は docs/VERSIONS.md
の1件、両側保持で解決）、新規統合セル（ブリッジ fake61→
実バニラ 1.7.10、ダイレクト fake61→実バニラ 1.5.2＝暗号化
ログイン込み、61 の §1 ピング完全形）が全合格した。回帰
89 セル（74／73 の Stage E 全セル）も全合格し、統合セル
合計は 96 件。分割検証は全 4,780 件・合格 4,763・失敗 0・
スキップ 17 で、最終監査（全クラスの XML 実在＋全統合
セルのメソッド名一致）も合格した。Stage E で実バグ1件を
発見・修正した（下記「Stage E で見つけた実バグ」）。
**本物の 1.5.2 クライアントでの確認は未実施。**

## 番号の規律

78／74／73 と同じ規律（docs/PROXY-1.6.4.md）：旧世代の番号は
legacy モジュール内にだけ置き、`ProtocolVersion` / `PacketIds`
には足さない。対応一覧は分けて数える。

## Stage A で実測確定した事項（2026-11-20）

土台：実バニラ 1.5.2 サーバー jar（piston-meta 由来、SHA-1
`f9ae3f651319151ce99a0bfad6b34fa16eb6775f` を再検証）を JDK 8 で
起動し、jar のバイトコード解析＋実ワイヤ採取（スポーン有効・
歩行あり）の両方で確定した。クライアント jar も piston-meta
から取得し SHA-1 `465378c9dc2f779ae1d6e8046ebc46fb53a57968` を
照合した。

### 抽出器の適応（1.5 世代の実装差）

1.5.2 のパケット読み書きメソッドは `DataInput` /
`DataOutput` インターフェースではなく具象クラス
`DataInputStream` / `DataOutputStream` を取る。78 の抽出器を
この署名に適応させて機械抽出した（文字列ヘルパーは
`a(DataInputStream, int)`、bytes16 は `b(DataInputStream)`）。
基底クラスは `ei`、登録は **79 件**。

### 結論：73⇔61 の差分は「欠落2件＋形式差6件」

**欠落（1.6 で追加されたため 61 に無い）：**

1. **0x1B steer_vehicle が無い**（乗り物の操作入力は 1.6 の
   馬と一緒に追加された）。
2. **0x2C entity_properties が無い**（属性システム自体が
   1.6 で追加）。73 にあって 61 に無いのはこの2件のみで、
   61 にあって 73 に無いパケットは無い。方向フラグは共有する
   全パケットで一致。

**形式差（共有パケットの読み列を役割正規化して比較し、
実バイトコードで個別に裏付けた）：**

3. **0x08 update_health：体力が I16**（73 は F32）。
   61 の形式は [I16 体力, I16 食料, F32 満腹度]。
4. **0x13 entity_action：末尾の I32 が無い**（73 は
   [I32, I8, I32]、61 は [I32, I8]）。馬ジャンプ等の補助値は
   1.6 で追加。
5. **0x27 attach_entity：末尾の U8（リードフラグ）が無い**
   （61 は [I32, I32]）。リード自体が 1.6 の追加。
6. **0x64 open_window：条件付き I32（馬ウィンドウの
   エンティティID）が無い**。馬がいないので当然の帰結。
   コーデックは 73 の `open_window` と分けた変種が要る。
7. **0xC8 statistics：量が I8**（73 は I32）。バイトコードで
   `readInt`（ID）＋`readByte`（量）を直接確認した。
8. **0xCA player_abilities：飛行／歩行速度が I8**
   （73 は F32）。バイトコードで `readByte / 255.0f` を直接
   確認した。書き戻しは `round(速度 × 255)`。

- 0x22 のヨー／ピッチは 61 が `read()`、73 が `readByte` で
  読むがワイヤ上は同一（1バイト）なので差分ではない。
  0xFE のパケットクラス読みは 61 では自明（セッション層で
  処理する現行設計に影響なし）。
- 委譲先ヘルパーも個別に確認：DataWatcher の型スイッチは
  **0〜6 の7種**（73／78 と同じ）、ItemStack の読みは
  [I16 ID, U8 個数, I16 ダメージ, I16 長さ＋gzip NBT] で
  78 と同一、チャンクバルク 0x38 の **skyLight フラグは
  61 にもある**（バイトコード＋実物 89 件のバルク解析で確認）。
  スロット NBT の gzip、entityMetadata の終端 0x7F、移動
  パケットの順序 [x, stance, feetY, z] も従来どおり。

### レジストリ差分（1.6 の追加分が 61 に無い）

クライアント jar の lang キー比較（61／73）：tile 197／232、
item 206／211、entity 43／49。61 にあって 73 に無いキーは
ゼロ（削除は無い）。1.6 の追加分：

- ブロック：170 干草の俵、171 カーペット（16色）、
  172 堅焼き粘土、173 石炭ブロック、159 色付き堅焼き粘土
  （16色）。
- アイテム：417／418／419 馬鎧（鉄／金／ダイヤ）、
  420 リード、421 名札。
- エンティティ：馬の一族（プロトコル5空間で mob 種別 100）。

**61 向けの近似方針**（家の流儀：系統を保ち、メタは維持）：

- ブロック：173→羊毛 35:15（黒）、172→粘土 82、
  159（メタ c）→羊毛 35:c（色を維持）、170→羊毛 35:4（黄）、
  171（メタ c）→羊毛 35:c（カーペットは羊毛なので系統維持）。
- アイテム：417→鉄のチェストプレート 306、418→金の
  チェストプレート 315、419→ダイヤのチェストプレート 310
  （素材と「鎧」であることを維持）、420→糸 287、
  421→紙 339。
- エンティティ：mob 種別 100（馬）→ 90（豚）。
  73／78 向けでは素通しだったスポーン種別に、61 向けだけ
  変換が要る。
- 0x64 の馬ウィンドウ（種別 11）を 61 向けに送る場合は
  エンティティIDを落とす（ウィンドウ自体は開く）。

### 実ワイヤ採取

実バニラ 1.5.2（offline、FLAT、スポーン有効）へ暗号化
ログイン（プロトコル 61）し、歩行＋チャット＋Keep Alive
応答を行った採取を、61 用に直した表（0x08 は I16 体力、
0xC8 は I8 量、0xCA は速度バイト、0x2C／0x85 無し）で
**383 パケットすべて末尾まで完全解析（ズレ0）**した。
チャンクバルクは 89 件（skyLight フラグ位置も検証）、
0xCA は新形式で解析でき、チャットはバニラのログに到達し、
プロトコルエラーは無かった。観察事項：1.5.2 サーバーは
MC|Brand を送ってこなかった（1.6.1 と同じ。プラグイン
メッセージは素通しなので実害は無い）。

### したがって実装方針は

- `LegacyPacketTable.V1_5_2` は 78 の表から作る実体マップ：
  0x85／0x1B／0x2C を除き（79 件）、0x08／0x13／0x27／0xC8／
  0xCA は専用レイアウト、0x64 は馬なし変種コーデック。
- 変換器（`LegacyPlayTranslator`）はクライアントプロトコルを
  既に知っているので、61 向けに：体力 F32→I16（四捨五入）、
  速度 F32→バイト（×255）、統計量 I32→I8（クランプ）、
  attach のリードフラグ落とし、entity_action の補助値
  補完（61 からは 0）、馬スポーン→豚、馬ウィンドウの
  エンティティID落とし、を足す。
- レジストリ近似は `LegacyChunkRemap` に 61 向け表を足す
  （78 向け表とは別。既存の 5→78 表は変更しない）。

## 実装（Stage B〜D、2026-11-20）

- `LegacyProtocol`：V1_5_2（=61）を追加。対応一覧は
  [78, 74, 73, 61]。
- `LegacyPacketTable.V1_5_2` は 78 の表から作る実体マップ
  （79 件）：0x85／0x1B／0x2C を除き、0x08（体力 I16）／
  0x13（補助値なし）／0x27（リードフラグなし）／0xC8
  （量 I8）／0xCA（速度バイト）は専用レイアウト、0x64 は
  専用コーデック `open_window_nohorse` に差し替えた。
- コーデック：`open_window_nohorse` は馬ウィンドウの
  エンティティIDを読み書きしない（フィールド列の形は
  open_window と揃え、値は常に null）。
- 変換器（`LegacyPlayTranslator`）の 61 向け処理：体力は
  F32→I16（四捨五入）、attach はリードフラグを落とす、
  能力速度は双方向で float ⇔ バイト（×255／÷255、書きは
  0〜127 にクランプ）、属性（0x2C）は表に無いので落とす、
  馬（種別 100）は豚（90）でスポーン、entity_action の
  補助値は 0 を合成、スロット／メタデータ／チャンク／
  ブロック変更は 61 向け近似表を使う。
- レジストリ近似（`LegacyChunkRemap`）：78 表の後に適用する
  61 層を追加。チャンク内では石炭ブロック→黒羊毛・干草→
  黄羊毛のメタ強制もニブル配列へ書き込む。
- ダイレクトモード・アダプタ（`V1_5_2Adapter`、ブロック
  集合は代表集合内では 1.6.1 と同じ）・Java 8 配線・
  versionedJars は 74／73 と同じ形で追加。
- 単体テスト：レガシーモジュール 101 件を含む分割検証を
  実施（集計は split-verification-61/ と Stage D コミットを
  参照）。

## Stage E で見つけた実バグ（2026-11-20、修正済み）

- **`VanillaLogParser` が 1.5 世代の参加記録を読めなかった**：
  実バニラ 1.5.2 のログには「NAME joined the game」の行が
  無く、参加は「NAME[/ip:port] logged in with entity id N
  at (...)」の行だけで記録される（1.6.x は両方の行を出す。
  実バニラ 1.5.2 の server.log で実測）。パーサーは後者しか
  見ていなかったため、ダイレクトモードの新規セル3件が初回
  実行で「参加が現れない」失敗になった（初回失敗の XML は
  split-verification-61/ に証拠として保持）。フロント
  エンド側のログイン自体は正常だった。修正：logged in 行を
  参加イベントとして扱い、続く joined 行の二重発火を名前
  単位で抑制する（全世代で参加イベントは1回だけになる）。
  パーサーの単体テストを追加し、修正後に3セルとも参加→
  チャット→Keep Alive 応答→2通目のチャット到達まで実
  バニラのログで確認できた。このパーサーは本番の
  GameBridge も使うため、1.5 世代バックエンドでは参加
  イベントが本番でも発火しない実バグだった。

## 制限（正直な一覧）

- Stage E の裏付けは偽レガシークライアント＋実バニラの
  統合セルまで。本物のゲームクライアントでの確認は
  未実施（次節）。
- 本物の 1.5.2 クライアントでの確認は未実施。
- 1.6 の追加要素は近似・落としで処理する：カーペット等は
  羊毛化（色は維持）、馬は豚としてスポーン、馬鎧は
  チェストプレート化、リード・名札は糸・紙化、属性
  （0x2C）は同期されない、乗り物操作（0x1B）は無い。
  馬ウィンドウ（種別 11）はエンティティID無しで開く。
- 体力は整数化されるため、現代側の小数体力（例：19.5）は
  四捨五入されて届く。能力速度はバイト量子化（1/255 刻み、
  上限約 0.498）される。統計（0xC8）はブリッジモードでは
  従来どおり届かず（現代 0x37 は全レガシー共通で未変換）、
  ダイレクトモードでは量がバイトに切り詰められる。
- ピングは最古対応版（1.6.1）の挙動に揃えた応答のまま
  （素の FE01 には旧形式）。61 自体のピング癖は Stage A で
  採取していない。
- 旧世代は offline 前提（online 認証は成立しない）。
  詳細は docs/PROXY-1.6.4.md の制限節を参照。
