# DetergentMC 26.2 実機プレイテスト — チェックリスト

## 0. この手順書の読み方：プロトコル検証済み／実機でしか確認できないもの

### A. プロトコルレベルで既に検証済みの項目（実機では「同じことが起きるか」の確認）

- パケットIDの付け替え（775→776は0件変更。唯一の違いは play toServer 0x3e の改名
  `spectate_entity` → `spectator_action`）とレジストリの付け替え（ブロック状態+2,493・
  アイテム+31・音+66・パーティクル+8・属性+5）は単体テストで確認済み
- ペイロード差分4件（Join Game 末尾の onlineMode、Login Success 末尾の sessionId、
  Teams の並び替えと色の再編、SpectatorAction の OptionalInt 化）は単体テストで確認済み
- リソースパック776（pack_format 88）の生成と配信、Bedrock→776の配線は単体テストで確認済み
- 偽776クライアントがプロキシ経由で本物のバニラ26.2／26.1／1.21.11／1.20.1に参加できることは
  Stage E の統合テスト（`ProxyIntegrationTest` の5セル）で確認予定。2026-11-15時点では
  まだ実行していないため、この手順書の「参加」は実機での初確認になる

### B. 実機でしか確認できない項目（この手順書の本題）

- 26.2の本物のゲームクライアントで参加できるか（プロトコルレベルでは偽クライアントしか使っていない）
- 硫黄系ブロック・硫黄キューブ・間欠泉のパーティクル・新レコード bounce が見える／聞こえるか
- リソースパック776が「互換性あり」と表示され、泡テクスチャが変わるか
- 2人のプレイヤーがお互いに見えるか（偽クライアントでは確認できない。最重要）
- チームの色・観戦（SpectatorAction）の実機での挙動
- インベントリ操作・チャット・次元移動の実機での挙動

## 1. 起動

### 1.1 準備（初回のみ）

```sh
cd ~/workspace/detergentmc
./gradlew build :bubbles:hello-bubble:jar
cp bubbles/hello-bubble/build/libs/hello-bubble-0.1.0-1.20.4.jar run/bubbles/
```

`run/eula.txt` と `run/vanilla/eula.txt` が `eula=true` になっていること。

### 1.2 起動（ファットjar・推奨）

```sh
java -Dfile.encoding=UTF-8 -jar build/libs/detergentmc-0.1.0-1.20.4.jar
```

Gradle経由の `./gradlew :detergentmc-core:runServer` ではコンソール入力が
届かないので、対話するなら上の `java -jar` で起動すること。

起動完了の目安：`Done (...)!` と `バニラサーバーが起動しました (ポート 25565)。`

この手順書の参加テストでは、サーバーはまず **26.2** のまま
（`minecraft-version: "26.2"`、既定ではないため設定で変える。下の「1.5」を参照）
で、26.2クライアントがプロキシ経由で参加する。サーバー自体を
1.19系・1.20系・1.21系・26.1で動かす場合は下の「1.5 サーバーを別バージョンで動かす場合」を参照すること。

### 1.4 online-mode／offline-modeの切替方法

`run/detergentmc.yml` の `server.online-mode` を変える。既定は `true`
（プロキシがMojang認証を完結させる）。実機で正規アカウントを使わない
確認（オフラインの動作確認だけ）なら `false` にする。内部バニラは常に
offline-mode（信頼済み接続）で動くため、ここの切替はプロキシ認証の
オン／オフである。

```yaml
server:
  online-mode: false
```

#### Java 21 の注意（1.20.5／1.20.6／1.21／1.21.1／1.21.2／1.21.3／1.21.4／1.21.5／1.21.6／1.21.7／1.21.8／1.21.9／1.21.10／1.21.11サーバーのときだけ）

バニラ1.21.11サーバーは Java 21 を要求する。DetergentMC本体は
Java 17 で動く。`VanillaServerHost` は次の順番で Java 21 を探す。

1. `detergentmc.java21.home` システムプロパティ、
2. `DETERGENTMC_JAVA21_HOME` 環境変数、
3. 現在の `java.home` が Java 21 以上のときはそれ、
4. どれも無いときは現在の Java を使うが、バニラが起動を拒否する。

ファットjarを Java 17 で起動したまま、内部だけ Java 21 にする例：

```sh
DETERGENTMC_JAVA21_HOME=$HOME/workspace/.tools/jdk-21.0.13+9 \
  java -Dfile.encoding=UTF-8 -jar build/libs/detergentmc-0.1.0-1.20.4.jar
```

ファットjar自体を Java 21 で起動してもかまいません（その場合は3. の経路）。

## 2. 参加（26.2クライアント）

26.2の本物のゲームクライアントで、プロキシの公開ポート
（既定25565）に接続する。サーバーリストには **26.2**（protocol 776）と
表示されるはずである。

参加直後にリソースパックの提示が出る（776用パック pack_format 88）。
「はい」を選ぶとパックが適用される。パックの提示が出ない場合は、
`resource-pack.enabled` が `true` になっていることと、25567番ポートの
配信を確認すること。

## 付録：外部配信（`resource-pack.url-776` / `sha1-776`）の設計

`detergentmc.yml` の `resource-pack.url-776` / `sha1-776` に外部URLとSHA-1を
書くと、776クライアントにはそのパックを出す（既定はloopback配信）。
