# プロトコル39（Minecraft 1.3.2／1.3.1）対応ノート

DetergentMC のレガシーフロントエンド（`detergentmc-legacy-frontend`）がプロトコル39
（**1.3.2／1.3.1**）を受けられるようにした記録。Stage A の実測が正であり、
本文書の数値はすべて実 jar・実バニラからの採取に基づく。

番号対応：**39 ＝ 1.3.2 と 1.3.1 の両方**（先行調査 `legacy-prep-old/PREP-OLD.md` の
レガシーピング＋ハンドシェイク探測で実測。流布表の「1.3.1 ＝ 38」は誤りで、
1.3.1 も 39。38 はどの製品版にも対応しない）。39 は Netty 以前世代の番号であり、
legacy モジュール内にのみ置き、`ProtocolVersion` には入れない。

## Stage A：実測（1.3.2／1.3.1 サーバー jar、JDK 8）

- バニラ 1.3.2 サーバー jar SHA-1 `3de2ae6c488135596e073a9589842800c9f53bfe`、
  1.3.1 サーバー jar SHA-1 `82563ce498bfc1fc8a2cb5bf236f7da86a390646`、
  1.3.2 クライアント jar SHA-1 `c2efd57c7001ddf505ca534e54abf3d006e48309`
  （いずれも piston-meta 照合済み）。
- パケット登録は両 jar から機械抽出（基底クラス `db`）。**登録 75 件**で、
  ID 集合・方向フラグは旧47（1.4.2）と完全一致。
- 旧47⇔39 の差分は次のとおり（機械抽出の全件比較＋該当クラスの
  バイトコード直接確認）。ワイヤ形式の差分は **5 件**：
  1. **0x04 time_update が I64×1**（旧47 は I64×2）。1.3.2 のワールドは
     時刻を 1 本だけ保持する（NBT キー "Time"。worldAge／dayTime の
     分割は 1.4 の追加で、クライアント jar の WorldInfo でも確認）。
     サーバーが送るのはその 1 本であり、`/time set` や就寝で動く値
     ＝現代側の timeOfDay に相当する。
  2. **0x15 pickup_spawn が展開形**：entityId I32、itemId I16、count U8、
     damage I16、x/y/z I32、yaw/pitch/roll I8。**NBT は無い**
     （旧47 は entityId＋スロット丸ごと）。1.4 でスロット形に変わった。
  3. **0x3D effect に末尾 BOOL が無い**（5 フィールド。global フラグは 1.4 の追加）。
  4. **0xCC client_settings に末尾 BOOL が無い**（4 フィールド。
     showCape は 1.4 の追加）。
  5. **0xFE server_list_ping のパケットクラスにフィールドが無い**
     （旧47 は I8 を 1 つ読む。実バニラ 1.3.2 は素の FE 01 に対して
     旧形式 `<MOTD>§<人数>§<上限>` で応答し、PingHost 付きの完全形には
     接続リセットで応えることを先行調査で実測済み。フロントエンドは
     従来どおり完全形が来れば §1 形式、来なければ旧形式で応答する
     ＝実バニラより広く受ける側に倒した互換動作）。
  - なお 0x66 window_click の actionNumber は 39 が BOOL、旧47 が I8
    （どちらも 1 バイトで、0/1 の意味も同じ＝通常クリック／シフト
    クリック。現代側 mode バイトへの写像は不変）。
- チャンク：0x33／0x38 のスキーマは旧47 と同一で、バルクは
  **skyLight フラグ無し**（フラグは 51 から、という実測が 39 でも
  成り立つ）。セクション中身（10240 バイト＋追加配列 2048＋
  バイオーム 256）も 1.7 世代と同一レイアウト。
- 補助形式：
  - スロット読み（基底クラス `db.c` 経由）は旧47 と同形
    （I16 id＋U8 個数＋I16 ダメージ＋NBT）。
  - **DataWatcher の type 5（スロット）は id／個数／ダメージのみで
    NBT が無い**（1.3.2・1.4.2 の両 jar の DataWatcher 読み取りで
    実測）。完全スロット形の watcher は 1.4.4／1.4.5 の jar で
    確認でき、**境界は {39, 旧47} と {49 以降} の間**にある。
    フロントエンドは従来 watcher スロットを全世代で完全スロット
    として読み書きしていたため、旧47 のメタデータ内スロットは
    実際には誤解析していたことになる。今回 39 の追加にあわせて
    旧47 も含めて正しい形に直した（Stage B）。
- レジストリ差分（両 jar の Block/Item 登録のバイトコード確認＋
  エンティティ登録の機械比較）。1.4 の追加分が 39 に無い：
  - **ブロック 9 件が無い**：137 コマンドブロック、138 ビーコン、
    139 石畳の壁、140 植木鉢、141 ニンジン、142 ジャガイモ、
    143 木のボタン、144 頭（スケルトン等の頭蓋）、145 金床。
    1.3.2 の最大ブロック ID は 136（ジャングル木の階段）。
  - **アイテム 12 件が無い**：389 額縁、390 植木鉢、391 ニンジン、
    392 ジャガイモ、393 焼きジャガイモ、394 青くなったジャガイモ、
    395 白紙の地図、396 金のニンジン、397 頭、398 ニンジン付きの竿、
    399 ネザースター、400 パンプキンパイ。
    レコードは 2256〜2266 が両 jar にあり、2267 はどちらにも無い。
  - **エンティティ 5 件が無い**：オブジェクト 18 額縁、19 ウィザーの頭蓋、
    モブ 64 ウィザー、65 コウモリ、66 魔女。
  - オブジェクトスポーン（0x17）の種別番号は EntityList の ID では
    なく古典的な固定表で、1.3.2 のトラッカー／クライアントでも
    経験値ボトルは **75**（現代の 74 とは違う）。フロントエンドの
    現代側番号は独自ハイブリッドで種別は素通しのため、この差は
    現状の設計では吸収も変換もしていない観察事項として残す。
- 実ワイヤ採取（実バニラ、暗号化ログイン＋歩行＋チャット）：
  - 1.3.2：78 パケットを末尾までズレなく解析（オフライン再解析でも
    ストリームをちょうど消費）。チャンクバルク 17 件すべてで膨張後
    サイズが Σ（セクション数×10240＋追加配列×2048＋256）と一致。
    0x04 が 9 バイト（ID＋I64×1）で流れることもワイヤで確認。
    チャットはサーバーログに到達。
  - 1.3.1：1,241 パケットを完全解析（バルク 17 件サイズ一致、
    チャット到達）。ログイン暗号化（RSA-1024＋AES/CFB8）は
    39〜78 共通の手順がそのまま使えた。
- **1.3.1⇔1.3.2 は差分ゼロ**：登録 75 件・スキーマ（難読化クラス名を
  正規化して比較）・レジストリ（ブロック／アイテムの名前対応）・
  エンティティ登録がすべて一致し、実ワイヤでも同じ表で解析できた。
- pack_format の概念はこの世代に無い（テクスチャパックは
  MC|TPack で配送）。DataVersion の概念も無い。

  名前付きパーティクルは無い、体力は I16 へ丸め、能力速度は
  バイト量子化、馬はブタ、属性／乗り物操作は無い。

## 実装（Stage B〜D、2026-11-20）

- `LegacyProtocol`：定数 `V1_3_2`（= 39）を追加。対応レガシー一覧は
  [78, 74, 73, 61, 60, 51, 49, 47, 39] に固定。版名 "1.3.2"／"1.3.1"
  ⇔ 39 の対応、`is1_3Generation` の新設、watcher スロットの
  NBT 無し判定（`watcherSlotHasNoNbt` ＝ {旧47, 39}）を追加。
  世代特性（I16 体力・リーシュフラグ無し・速度バイト・馬なし）は
  51 世代と同一のため `is1_5OrOlderGeneration` に 39 を含めた。
- `LegacyPacketTable`：`V1_3_2` 表は旧47 表のコピーに実測差分
  5 件（0x04／0x15／0x3D／0xCC／0xFE）を適用したもの。
- `LegacyPacketIO`／`LegacyWire`：新コーデック
  `pickup_spawn_expanded`（フィールド形は pickup_spawn と同一に
  保ち、ワイヤだけ展開形にする）。DataWatcher のスロット読み書きに
  「NBT 無し」形を追加し、39 と旧47 に適用した（旧47 の従来の
  読みは実 jar と違う形だったことの訂正を含む）。
- `LegacyChunkRemap`：39 専用層（ブロック 9 件・アイテム 12 件）を
  旧47 層の後に追加。
- `LegacyPlayTranslator`：0x04 の単一時刻化、0x3D の global 落とし、
  ウィザー／コウモリ／魔女→ブタ、鉱車バリアントの素通し条件への
  39 の追加、client_settings の showCape 合成、スロット変換への
  39 分岐を追加。
- アダプタ：`V1_3_2Adapter`／`V1_3_1Adapter`（どちらも
  protocolVersion は 39）を legacy モジュールに追加し
  ServiceLoader に登録。コア側は `minecraft-version: 1.3.2`／
  `1.3.1` でダイレクトモード配線（`LegacyWiringTest`）、内部
  バニラの Java 8 対象に "1.3.2"／"1.3.1" を追加、
  versionedJars の版リストに '1.3.1'／'1.3.2' を追加。
- 単体テスト：対応一覧の固定（39 を含む）、39⇔旧47 の表差分が
  ちょうど 5 件であることの固定、展開形 pickup の往復、
  watcher スロット NBT 無しの往復（39 と旧47）、変換器
  （時刻・effect・1.4 モブとアイテム）、チャンク近似、
  E2E（ダイレクト中継・ブリッジの 0x85／0x2C 落とし・§1 ピング
  39 / 1.3.2 と 39 / 1.3.1）、アダプタ・配線テストを追加。
  分割検証の総数は docs/VERSIONS.md の 39 節を参照。

## 検証の範囲と残る制限

- **Stage E（実バニラ統合）完了（2026-11-20）**。旧47 の
  Stage E 最終 HEAD `d0bd417` へリベースし、新規セル 5 件
  （ブリッジ fake39 → 実 1.7.10、ダイレクト fake39 → 実
  1.3.2 の暗号化ログイン込み、ダイレクト fake39 → 実
  1.3.1 の暗号化ログイン込み、§1 ピング完全形、素の
  FE 01 への旧形式応答）と回帰 105 セルで **統合 110 セル
  すべて合格**、分割検証は **4,883 件・合格 4,866・
  失敗 0・スキップ 17**、最終監査も合格。Stage E で
  見つけた実バグは無し。Stage A の裏付けは jar 機械抽出
  （1.3.2／1.3.1 の両方）＋実バニラへの採取セッション
  （1.3.2 は 78 パケット、1.3.1 は 1,241 パケットを
  完全解析）。
- **本物の 1.3.2／1.3.1 ゲームクライアントでの確認は未実施**。
  特にブリッジモードでアイテム実体を 0x17 種別 2 で送る方式が
  実クライアントで表示できるかは 49 世代から引き継いだ
  未確認点（docs/PLAYTEST-1.3.2.md の最重点項目）。
- 旧世代は offline 前提（Mojang の旧認証エンドポイントが
  廃止されているため）。ブリッジモードはコアの
  offline-mode が前提。
- watcher スロットの NBT 無し訂正は旧47 の挙動も変える
  （実 jar に基づく訂正）。旧47 の系統では Stage E 準備で
  同等修正が移植され、39 の Stage E のリベースでは両系統の
  実装が重複したため、正しい実装を 1 つだけ残して統合した
  （両世代の固定テストが共に合格）。旧47 側の統合確認は
  旧47 の Stage E で実施済み（ただし実トラフィックに
  スロット入りメタデータは現れず、実地の裏付けは未実施）。
- オブジェクトスポーン種別はフロントエンドのハイブリッド番号を
  素通しする設計で、経験値ボトル（実 jar では 75）のような
  世代差は未変換のまま残る観察事項。
