# DetergentMC 1.9.4 実機プレイテスト — チェックリスト

2026-11-19 作成、Stage A〜D 完了に合わせて作成（Stage E 完了に
合わせて冒頭の状態を更新）。1.9.4 クライアント
（プロトコル110）で各サーバーに参加する実機確認のための手順と、
結果の記録用。詳細な仕組みは `docs/PROXY-1.9.4.md` を参照。

## 0. この手順書の読み方

DetergentMC の 110 対応は **Stage E まで完了**。単体テスト
（分割検証 4,266 件・失敗 0）と Stage A のワイヤ採取に加え、
**実バニラ統合テスト（ProxyIntegrationTest の統合セル
新規 3 件＋回帰 56 件の全 59 件）が合格済み**。ただし
**本物のゲームクライアントでの確認は未実施**。この
チェックリストはその実機確認のためのものである。なお統合セル
では、プロキシが 110 向けに補う空 hash の Resource Pack
Response を実バニラ 1.9.4 が受け付けること（切断されず、
その後のチャットが到達すること）も確認済みである。

110 は 1.9.4 と 1.9.3 の2リリース共通プロトコルで、210（1.10.2）
との差分はパケットID差分 0 件・形式差分ちょうど 3 件。実機では
特に、**形式差分 3 件の見え方**（音のピッチ感、リソースパック
応答の流れ）、**近似の見え方**（magma→netherrack、
bone_block→quartz_block、polar_bear→ブタ等）、**Keep Alive
（varint）の長時間セッションでの安定性**が重点になる。

### A. 単体テストで検証済みの項目（実機では再現の確認）

- 110 のパケット ID 表が 210 と全件一致（`PacketIds110Test`：
  id110 == id210 を全 283 エントリで固定。110 に存在するのは
  113 件）。
- 対応クライアント一覧の最古が 110 で、210／315／316 が残り、
  計 37 プロトコル（`ClientAdapter110Test`。最古脱落の罠を
  固定）。
- 形式差分 3 件の境界変換（`ChunkTranslator110Test`、
  `ProxySession110Test`）：音 pitch の u8⇔f32 換算
  （1.0→64、0.5→32、2.0→127 の量子化）、resource_pack_receive
  の hash 付け外しと往復。
- レジストリ写像の代表値と往復（`RegistryRemapper110Test`）：
  magma→netherrack、nether_wart_block／red_nether_brick→
  nether_brick、bone_block→quartz_block（メタ保持）、
  structure_void→barrier、structure_block アイテム→barrier
  アイテム、110 に無いアイテム（213–217・255）が 110 側に
  生成されないこと、polar_bear→ブタ、fallingdust→explode、
  音の名前照合（block.stone.break は 210 の 375 ⇔ 110 の 364）。

### B. 実機でしか確認できない項目

- [ ] 1.9.4 クライアントで 1.9.4 サーバー（内部）に参加し、
      チャンク表示・移動・チャットが正常か。
- [ ] 1.9.3 クライアントでも同様に参加できるか（110 は
      1.9.3 もカバーする）。
- [ ] 1.9.4 クライアントで新しいサーバー（例：1.20.4）に
      参加できるか。音のピッチが極端にずれて聞こえないか
      （特に音程の高い音・低い音）。
- [ ] 新しいクライアント（例：1.20.4）で 1.9.4 サーバーに
      参加し、1.10 追加ブロック（magma 等）の場所が近似
      ブロックで表示されるか。
- [ ] リソースパックの要求→応答の流れが 1.9.4 クライアントで
      完走するか（空 hash の受け付け確認を含む）。
- [ ] polar_bear のいる場所でブタとして表示されるか
      （1.9.4 クライアント→新しいサーバー）。
- [ ] Keep Alive（varint）世代のため、30 分以上の接続で
      切断されないか。
- [ ] 2 人以上のプレイヤーが互いに見えるか（全バージョン
      共通の最優先確認項目。偽クライアントでは検証不能）。
