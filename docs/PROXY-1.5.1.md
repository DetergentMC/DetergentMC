# プロトコル60（Minecraft 1.5.1／1.5）— Netty 以前世代フロントエンド

DetergentMC の Netty 以前世代フロントエンド（モジュール
`detergentmc-legacy-frontend`、docs/PROXY-1.6.4.md）の第5弾。
レガシープロトコル 60（1.5.1 と 1.5 の両方）を 78／74／73／61
と同じ基盤に追加する。

**状態：Stage E 完了（2026-11-20）。** 61 と同じリベースの
上で、新規統合セル（ブリッジ fake60→実バニラ 1.7.10、
ダイレクト fake60→実バニラ 1.5.1＝暗号化ログイン込み、
ダイレクト fake60→実バニラ 1.5＝暗号化ログイン込み、
60 の §1 ピング完全形）が全合格した。統合セル合計・
分割検証の最終集計は 61 の Stage E と同一（同一ツリー、
docs/PROXY-1.5.2.md を参照）。Stage E で見つけた実バグ
（VanillaLogParser の 1.5 世代参加行）も 61 と共通で、
修正済み。
**本物の 1.5.1／1.5 クライアントでの確認は未実施。**

## 番号の規律

従来と同じ規律（docs/PROXY-1.6.4.md）：旧世代の番号は legacy
モジュール内にだけ置き、`ProtocolVersion` / `PacketIds` には
足さない。対応一覧は分けて数える。60 は **1.5.1 と 1.5 の
2つのリリースを1つのプロトコルで受ける**（実測は下記）。

## Stage A で実測確定した事項（2026-11-20）

土台：実バニラ 1.5.1 サーバー jar（piston-meta 由来、SHA-1
`d07c71ee2767dabb79fb32dad8162e1b854d5324` を再検証）と
1.5 サーバー jar（SHA-1
`aedad5159ef56d69c5bcf77ed141f53430af43c3`、piston-meta では
snapshot と誤ラベルされているが製品版で公式 jar がある）を
JDK 8 で起動し、バイトコード解析＋実ワイヤ採取の両方で
確定した。クライアント jar も piston-meta から取得し、
1.5.1 は SHA-1 `047136381a552f34b1963c43304a1ad4dc0d2d8e`、
1.5 は SHA-1 `a3da981fc9b875a51975d8f8100cc0c201c2ce54` を
照合した。

### 結論：61⇔60 のワイヤ差分はゼロ、レジストリ差分もゼロ

- 1.5.1 のパケット登録は **79 件**で 61 と集合が一致し、
  共有する全 79 パケットの読み書き呼び出し列が、61 用に
  適応した抽出器（docs/PROXY-1.5.2.md の Stage A）の出力で
  **完全一致**した。方向フラグも全て一致。61 の形式差
  6件（体力 I16 等）はそのまま 60 にも当てはまる。
- **1.5 も同じ**：1.5 の jar でも登録 79 件・読み書き列は
  1.5.1 と完全一致した（差分として出るのは難読化クラス名
  の違いだけ）。→ プロトコル 60 は 1.5.1 と 1.5 の両方を
  カバーする。
- レジストリ差分：クライアント jar の lang キーを比較し、
  tile（197）・item（206）・entity（43）のキー集合が
  1.5.2／1.5.1／1.5 で完全一致。lang 全体の差分は Realms の
  UI 文字列（mco.*）とチャットリンク・セーブ通知の文字列
  だけで、ワイヤには無関係。→ `LegacyChunkRemap` の 61
  向け近似表は 60 でもそのまま使える。

### 実ワイヤ採取

- 実バニラ 1.5.1（offline、FLAT、スポーン有効）へ暗号化
  ログイン（プロトコル 60）し、歩行＋チャット＋Keep Alive
  応答を行った採取を 61 用の表で **3,534 パケットすべて
  末尾まで完全解析（ズレ0）**した。チャンクバルクは
  89 件、チャットはバニラのログに到達した。
- 実バニラ 1.5（同条件）でも同じ採取を行い、**823
  パケットすべて完全解析（ズレ0）**した。チャットも
  ログに到達した。
- どちらのサーバーも MC|Brand は送ってこなかった
  （1.5.2／1.6.1 と同じ）。

### したがって実装方針は

- `LegacyPacketTable.V1_5_1` は 61 の表への**全面委譲**
  （74 が 78 へ委譲したのと同じ形）。
- `LegacyProtocol`：V1_5_1（=60）を追加し、バージョン名は
  "1.5.1" と "1.5" の両方を 60 に対応付ける（正規名は
  "1.5.1"）。対応一覧は [78, 74, 73, 61, 60]。
- 変換器・チャンク近似の「61 向け」分岐は「1.5 世代
  （61 と 60）」に読み替える。ワイヤが同一なので挙動は
  変わらない。
- アダプタは `V1_5_1Adapter` と `V1_5Adapter` の2つ
  （`minecraft-version` はどちらの名前でも受けられる
  ように）。Java 8 配線・versionedJars も両名を追加。

## 実装（Stage B〜D で入れたもの）

方針どおりに実装した：

- `LegacyPacketTable.V1_5_1` は 61 の表そのもの（全面委譲）。
  テストで項目ごとの一致を固定している。
- `LegacyProtocol` に V1_5_1（=60）と `is1_5Generation`
  （61 と 60 の両方に真）を追加。変換器
  （`LegacyPlayTranslator`）とチャンク近似
  （`LegacyChunkRemap`）の「61 向け」分岐はすべて
  `is1_5Generation` に付け替え、60 クライアントにも
  61 と全く同じ変換（体力 I16 化、速度バイト変換、馬→豚、
  61 向け近似表など）が効くようにした。
- バージョン名は "1.5.1" と "1.5" の両方を 60 に
  対応付け（正規名は "1.5.1"）。§1 ピングは設定された
  バックエンド名をそのまま広告するので、`1.5` 設定では
  "1.5" と出る。
- アダプタ `V1_5_1Adapter` / `V1_5Adapter` を
  META-INF/services に登録。`VanillaServerHost` は両名を
  Java 8 で起動し、`versionedJars` にも両名を追加した。
- 単体テスト：レガシーモジュール 112 件を含む分割検証
  （下記 Stage D コミット参照）。

## 制限（正直な現状）

- Stage E の裏付けは偽レガシークライアント＋実バニラの
  統合セルまで。実機確認の手順は docs/PLAYTEST-1.5.1.md。
- **本物の 1.5.1／1.5 クライアントでの確認は未実施**。
  Stage A の採取は自作クライアントによるものである。
- 近似・落とし物は 61 と全く同じ（docs/PROXY-1.5.2.md の
  制限節を参照）：体力の整数化、速度のバイト量子化と上限、
  1.6 追加分の近似、属性・乗り物操作・統計の落とし、馬
  ウィンドウの ID 無し、など。
- この世代は **offline 前提**（旧クライアントの online
  認証は Mojang 旧エンドポイント廃止のため成立しない）。
  暗号化ログイン自体は offline でも必須で、実装済み。
- 1.5.1 と 1.5 の違いは Realms の UI 文字列などワイヤに
  出ない部分だけ（実測）だが、実クライアント同士の相互
  運用は未検証である。
