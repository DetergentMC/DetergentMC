# DetergentMC 1.7.10 実機プレイテスト — チェックリスト

2026-11-19 作成、Stage A〜D 完了に合わせて作成。2026-11-20
に Stage E 完了（実バニラ統合74セル全合格・分割検証
4,601件失敗0）。1.7.6〜1.7.10 クライアント（プロトコル5）
で各サーバーに参加する実機確認のための手順と、結果の
記録用。詳細な仕組みは `docs/PROXY-1.7.10.md` を参照。

## 0. この手順書の読み方

DetergentMC の 5 対応は **Stage E まで完了**。単体テスト
（分割検証）と実バニラ統合テスト（ProxyIntegrationTest の
統合セル：fake5→実 1.7.10、fake5→実 1.8.9、fake47→実
1.7.10 を含む）で確認済みだが、**本物のゲームクライアント
での確認は未実施**。このチェックリストはその実機確認の
ためのものである。

5 は 47（1.8系）とパケット ID が完全一致する一方、形式差分は
60パケットに及ぶ。実機での重点は：**チャンク表示（種類別
グループ化レイアウトの変換と Map Chunk Bulk 分割）が正しい
こと**、**Keep Alive（i32）の長時間セッションでの安定性**、
**名前ベース Player Info と named_entity_spawn の合成で
他プレイヤーが正しく見えること**、**リソースパックの申し出
（MC|RPack）が 1.7 クライアントに届くこと**、
**スロットの gzip NBT 変換でインベントリが崩れないこと**。

### A. 単体テストで検証済みの項目（実機では再現の確認）

- 5 のパケット ID 列（`PacketIds5Test`：47 と共通95件・
  ID 差分0、47 専用12件は 1.8 の追加分）。
- 対応一覧の先頭＝5、47・107〜316 が残存、計42プロトコル
  （`ClientAdapter5Test`。最古脱落の罠の固定）。
- レジストリ合成（`RegistryRemapper5Test`：共有名は恒等、
  1.8 追加分は近似表、音名の双方向変換）。
- チャンク往復と Bulk 分割（`ChunkTranslator5Test`）。
- スロットの damage 付け替え・gzip NBT・メタデータ bitfield
  往復（`SlotTranslator5Test`）。
- Join Game の末尾1バイト差、Keep Alive の i32⇔i64 付け替えと
  復元、Player Info／Named Spawn の合成（`ProxySession5Test`）。
- Stage E の実バグ修正：5 バックエンドへの移動 stance 合成と
  プラグインメッセージ長付け、Join Game の entityId を使う
  腕アニメーション合成（`ProxySession5Test`）、47 クライアント
  の Login Success 文字列 UUID 形式と 5 バックエンドへ
  Teleport Confirm を合成しないこと（`ProxySession47Test`）。
- 実バニラ統合：fake5→実 1.7.10／fake5→実 1.8.9／fake47→
  実 1.7.10 の3セル＋回帰71セルの計74セル（`ProxyIntegration
  Test`）。MC|RPack の符号化も実ワイヤで確認済み。
- Bedrock 向け：5 チャンクと等価な 47 チャンクの翻訳一致、
  Named Spawn の文字列 UUID 読み（bedrock モジュールの
  `BedrockChunkTranslator5Test`／`BedrockEntityTranslator5Test`）。

### B. 実機で重点的に見る項目

1. **ログイン〜スポーン**：1.7.10 クライアントで 1.7.10／
   1.8.9／1.9／1.12.2／1.20.4 の各内部サーバーへ入り、
   地形が正しく表示されること（特にチャンク境界・光）。
2. **他プレイヤー表示**：2人で入り、相手の名前・スキン
   （プロパティ）が Named Spawn 経由で正しく出ること。
   タブリスト（名前ベース Player Info）の表示も確認。
3. **Keep Alive**：30分以上放置しても切断されないこと
   （i32 付け替えと復元表の実地確認）。
4. **インベントリ**：アイテムのダメージ値（道具の耐久）が
   正しく表示されること。NBT 付きアイテム（エンチャント等）
   の出し入れで壊れないこと。
5. **リソースパック**：パック設定時に 1.7 クライアントへ
   MC|RPack の申し出が届き、ダウンロードが始まること
   （符号化は Stage E で実ワイヤ確認済み。実機での申し出の
   見え方が確認対象）。
6. **移動と腕振り（Stage E の実バグ修正の確認）**：他バー
   ジョンのクライアント（1.8 等）で 1.7.10 バックエンドへ
   入り、移動が滑らかで切断されないこと。腕振りが他プレイ
   ヤーから見えること。
7. **チャンクの Bulk 配信**：ログイン直後の初期チャンクが
   欠けなく表示されること（Map Chunk Bulk 分割の確認）。
8. **近似の見た目**：1.8 のドア／フェンス／バナー等が
   1.7 クライアントで代替ブロックとして表示されること。
9. **音**：1.7 の音名が新しいクライアントで正しく鳴ること
   （REV 表の実地確認。逆も同様）。
10. **Bedrock → 1.7.10**：Bedrock クライアントで 1.7.10
   バックエンドへ入り、地形とエンティティが見えること。

### C. 既知の制限（実機でも再現する想定）

- 地図（PLAY_MAP）は表示されない（双方向とも未対応）。
- 1.7 バニラのチャット上限（約100文字）を超えるチャットは
  切断の原因になりうる。
- データパックが無い世代のため、トリガーブリッジ
  （/trigger d_hello 等）は 5 バックエンドでは使えない。
- タイトル表示はチャットへの代替表示になる。
