# プロトコル51（Minecraft 1.4.7／1.4.6）対応ノート

DetergentMC のレガシーフロントエンド（`detergentmc-legacy-frontend`）がプロトコル51
（**1.4.7 と 1.4.6**）を受けられるようにした記録。Stage A の実測が正であり、
本文書の数値はすべて実 jar・実バニラからの採取に基づく。

⚠️ **番号対応の訂正**：流布している対応表では 49 と 51 の帰属が逆に書かれていることが
多い（49＝1.4.6/1.4.7、51＝1.4.4/1.4.5）。先行調査（`legacy-prep-old/PREP-OLD.md`）の
レガシーピング §1 実測では **51＝1.4.7／1.4.6、49＝1.4.5／1.4.4** が正しい。
本実装・本文書は実測値を採用する。

## Stage A：実測（1.4.7 サーバー jar、JDK 8）

- バニラ 1.4.7 サーバー jar SHA-1 `2f0ec8efddd2f2c674c77be9ddb370b727dec676`
  （piston-meta 照合済み）。クライアント jar SHA-1 `53ed4b9d5c358ecfff2d8b846b4427b888287028`。
  1.4.6 サーバー jar SHA-1 `a0aeb5709af5f2c3058c1cf0dc6b110a7a61278c`。
- パケット登録は jar から機械抽出（基底クラス `ef`、read/write は 1.5.2 と同じく
  具象 `DataInputStream`/`DataOutputStream`）。**登録 74 件**。
- 61⇔51 の差分は次のとおり（61＝1.5.2 の機械抽出との全件比較）：
  1. **61 のみに存在するパケットが 5 件**：0x3F particle、0xCE scoreboard_objective、
     0xCF update_score、0xD0 display_scoreboard、0xD1 teams。
     スコアボード一式と名前付きパーティクルは 1.5 の追加。**51 のみに存在する
     パケットは無し**。共通 74 件の方向フラグ（CB/SB）は全件一致。
  2. **形式差は 1 件だけ**：0x64 open_window。61 は末尾に useTitle（BOOL）があるが、
     51 には無い（[I8, I8, STRING, I8]）。馬ウィンドウの entityId は 61 でも
     51 でも無い（それは 78 だけの形）。
  3. それ以外は 61 とバイト単位で同形：0x08 体力 I16、0x13 末尾 I32 無し、
     0x27 リーシュフラグ無し、0xC8 amount I8、0xCA 速度バイト（値/255）も
     すでに 51 に存在する（1.5 世代の特徴は 1.4 世代と共通）。
- 補助形式も 51 の jar 内で確認した：
  - DataWatcher（クラス `mj` の static `a`）：tableswitch 0〜6 の **7 型**、
    終端 0x7F。78/61 の METADATA コーデックと同一。
  - ItemStack 読み（`ef.c`）：I16 id、U8 個数、I16 ダメージ、NBT は `ef.d`
    （I16 長＋gzip NBT）。61 と同形。
  - **チャンクバルク 0x38 の skyLight フラグは 51 に存在する**（読み取り列
    [I16 件数, I32 長, BOOL skyLight, データ, チャンクごと I32/I32/I16/I16] を
    51 の jar で確認。prep の「51〜78 にある」を実測で裏付け）。0x33 単体チャンクも
    61 と同形。
- レジストリ差分（両 jar の Block/Item `<clinit>` 構築 ID 集合＋クライアント lang の
  差分の機械比較）：
  - **1.5 で追加されたブロックは 13 件（ID 146〜158）**：146 トラップチェスト、
    147 軽量用感圧板、148 重量用感圧板、149/150 レッドストーン反復装置（コンパレータ）、
    151 日照センサー、152 レッドストーンブロック、153 ネザークォーツ鉱石、
    154 ホッパー、155 クォーツブロック、156 クォーツの階段、157 起動レール、
    158 ドロッパー。削除は無し。
  - クォーツハーフブロックは新 ID ではなく石ハーフブロック（44）のメタ 7 の変種
    （二重ハーフ 43 のメタ 7 も同様）。
  - **1.5 で追加されたアイテムは 5 件**：404 コンパレータ、405 ネザーレンガ、
    406 ネザークォーツ、407 TNT付きトロッコ、408 ホッパー付きトロッコ。削除は無し。
  - エンティティ：モブ種別に変化なし。トロッコだけが 1.5 で分割された
    （51 は単一の "Minecart" 登録、1.5.2 は Rideable 42／Chest 43／Furnace 44／
    TNT 45／Hopper 46／Spawner 47）。ワイヤ上は spawn_object の種別 10＋
    data フィールドで運ばれるため、51 に存在しない変種（TNT=3、スポナー=4、
    ホッパー=5）は data を 0 に落とす。
- **1.4.6 は差分ゼロ**：1.4.6 jar の機械抽出でも登録 74 件・ID 集合一致・
  スキーマ差分 0 件、Block/Item 構築集合とエンティティ登録も完全一致。
  よってプロトコル51 は 1.4.7 と 1.4.6 の両方を 1 つの表でカバーする（60→61 と同じ委譲形）。
- 実ワイヤ採取（実バニラ 1.4.7、暗号化ログイン＋歩行＋チャット）：
  112 パケットを末尾までズレなく解析。内訳はログイン 1、チャンクバルク 34
  （チャンク 169 個、全バルクで skyLight=1、膨張後サイズが
  Σ（セクション数×10240＋追加配列×2048＋256）と全件一致＝セクション中身は
  1.7 と同一レイアウト）、Keep Alive 32（エコー確認）、時刻 36、チャット 1
  （サーバーログに到達を確認）。プロトコルエラー・切断なし。
- pack_format の概念はこの世代に無い（1.2.5〜1.6.4 はテクスチャパック）。
  DataVersion の概念も無い。

## 近似・落とすもの（51 向け）

- 1.5 追加ブロック（146〜158）は 51 に存在する近縁ブロックへ寄せる
  （`LegacyChunkRemap`、色・系統を優先）：トラップチェスト→チェスト（54）、
  軽量用感圧板→木の感圧板（72）、重量用感圧板→石の感圧板（70）、
  コンパレータ→リピーター（149→93／150→94）、日照センサー→石ハーフブロック
  （151→44、メタ 0 固定）、レッドストーンブロック→赤い羊毛（152→35、メタ 14 固定）、
  ネザークォーツ鉱石→ネザーラック（153→87）、ホッパー→ディスペンサー（154→23）、
  クォーツブロック→白い羊毛（155→35、メタ 0 固定）、クォーツの階段→オークの階段
  （156→53、メタ保持）、起動レール→パワードレール（157→27、メタ保持）、
  ドロッパー→ディスペンサー（158→23）。クォーツハーフは 44:7→44:1、
  43:7→43:1（砂岩、淡色）。
- 1.5 追加アイテム：コンパレータ→リピーター（404→356）、ネザーレンガ→レンガ
  （405→336）、ネザークォーツ→ダイヤモンド（406→264）、TNT／ホッパー付き
  トロッコ→通常トロッコ（407/408→328）。ブロックアイテム 146〜158 はブロック写像に乗る。
- スコアボード（0xCE/0xCF/0xD0/0xD1）と名前付きパーティクル（0x3F）は 51 に
  存在しないため 51 向けには落とす。統計（0xC8）は全レガシー世代で既に落としている。
- トロッコのスポーン data 3/4/5（TNT／スポナー／ホッパー）は 51 では 0
  （通常トロッコ）に落とす。data 1（チェスト）／2（かまど）は 51 にもあるので保持。
- 0x64 は専用コーデック `open_window_notitle`（useTitle 無し）。51 のタイトルは
  常にリテラルなので、内部形式では useTitle=true を補う。
- 1.5 世代と共通の制限はそのまま継承する：体力は I16 へ丸め、能力速度は
  バイト量子化（上限 ≒0.498）、馬（種別100）はブタへ、0x2C/0x1B はブリッジで落とす。

## 実装（Stage B〜D、2026-11-20）

- `LegacyProtocol`：V1_4_7（=51）を追加。対応一覧は
  [78, 74, 73, 61, 60, 51]。世代述語として `is1_4Generation`
  （51）と、1.5 世代と共通のワイヤ特性（体力 I16・リード
  フラグ無し・速度バイト・馬なし）をまとめた
  `is1_5OrOlderGeneration`（61／60／51）を追加した。
- `LegacyPacketTable.V1_4_7` は 61 の表から作る実体マップ
  （74 件）：0x3F／0xCE／0xCF／0xD0／0xD1 を除き、0x64 は
  専用コーデック `open_window_notitle` に差し替えた。
- コーデック：`open_window_notitle` は useTitle も
  エンティティIDも読み書きしない（フィールド列の形は
  open_window と揃え、読みでは useTitle=true を補う）。
- 変換器（`LegacyPlayTranslator`）の 51 向け処理：体力・
  attach・能力速度・馬→豚は 1.5 世代と共通の分岐
  （`is1_5OrOlderGeneration`）に付け替え。スコアボード
  （0xCE/0xCF/0xD0/0xD1）と名前付きパーティクル（0x3F）は
  表に無いので落とす（属性 0x2C と看板エディタ 0x85 の
  既存の落とし方と同じ形）。トロッコのスポーン data
  3/4/5（TNT／スポナー／ホッパー、1.5 の変種）は 0 に
  落とす。スロット／メタデータ／チャンク／ブロック変更は
  51 向け近似表を使う。
- レジストリ近似（`LegacyChunkRemap`）：61 層の後に適用
  する 51 層を追加。チャンク内では日照センサー→石
  ハーフブロック（メタ 0）・レッドストーンブロック→
  赤羊毛（メタ 14）・クォーツブロック→白羊毛（メタ 0）の
  メタ強制と、クォーツハーフ（44:7／43:7）→砂岩ハーフ
  （メタ 1）の変種付け替えもニブル配列へ書き込む。
- ダイレクトモード・アダプタ（`V1_4_7Adapter` と
  `V1_4_6Adapter` の両名、ブロック集合は代表集合内では
  1.5.2 と同じ）・Java 8 配線・versionedJars は 61／60 と
  同じ形で追加。
- 単体テスト：レガシーモジュール 134 件を含む分割検証を
  実施し、全 4,680 件・合格 4,663・失敗 0・スキップ 17
  （集計は split-verification-51/ を参照。Stage E で同フォルダを
  再利用したため、この A〜D 時点の XML は
  split-verification-51/xml-stage-d-backup/ に退避してある）。
