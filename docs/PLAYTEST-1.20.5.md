# DetergentMC 1.20.5／1.20.6 実機プレイテスト — チェックリスト

2026-11-09作成。1.20.5／1.20.6クライアント（プロトコル766）で1.20系サーバーに
参加する実機確認のための手順と、結果の記録用。既存の `PLAYTEST-1.20.1.md`
（1.20.1クライアント用）・`PLAYTEST-1.20.2.md`（1.20.2クライアント用）・
`PLAYTEST-1.20.4.md`（1.20.4クライアント用）は直接いじらず、こちらを
1.20.5／1.20.6専用の手順書とする。

## 0. この手順書の読み方：プロトコル検証済み／実機でしか確認できないもの

DetergentMCの1.20.5／1.20.6対応は、ここに書く項目の多くを**プロトコルレベルでは
すでに検証済み**である（本物のバニラ子プロセス＋生ソケットで766クライアントを
装った統合テスト `ProxyIntegrationTest`、`ProxySession766Test`、
`ChunkTranslator766Test` など）。実機テストの目的は、プロトコルレベルでは見えない
「本物のゲームクライアントでの見た目・挙動」を確かめることである。以下の2つに
分けて読むこと。

### A. プロトコルレベルで既に検証済みの項目（実機では「同じことが起きるか」の確認）

- 766クライアントの1.20.1サーバー（内部763）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake766ClientJoinsRealVanilla1201ThroughProxy`）。
  内部763には設定フェーズが無いため、プロキシが Join Game の codec から
  Registry Data（766形式 0x07）と Finish Configuration を合成して送る
- 766クライアントの1.20.2サーバー（内部764）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake766ClientJoinsRealVanilla1202ThroughProxy`）。
  設定フェーズは764の Registry Data などを766形式へ変換して中継する
- 763クライアントの1.20.2サーバー（内部764）への参加・スポーン・移動・チャット
  （`ProxyIntegrationTest.fake763ClientJoinsRealVanilla1202ThroughProxy`）。
  763↔764のプレイ・ペイロード変換（`*764To763`／`*763To764`）を含む
- 766クライアントの1.20.4サーバー（内部765）への参加フロー（設定フェーズの中継・
  Registry Data の形式変換・Join Game 0x2B・Spawn Position 0x56）は
  `ProxySession766Test.join766Against765RelaysConfigWithTranslation` で単体
  テスト済み。統合テスト（本物のバニラ1.20.4＋偽766クライアント）は未実施
- 766クライアントの1.20.5／1.20.6サーバー（内部766）への参加は素通し（リレー）。
  `ProxySession766Test.join766Against766IsRelayedOffline` で単体テスト済み。
  プロキシが内部766で実起動して listen することは確認済み。統合テストは未実施
- `/trigger d_hello` / `d_lang_ja` / `d_lang_en` の動作（言語切替と保存を含む。
  1.20.4サーバーでの検証を流用）
- サーバーリストのpingでバージョンが **1.20.5**（protocol 766）と表示されること
  （`ClientAdapter766Test.rewriteStatusJsonFor766Client`）
- 766クライアントへのリソースパックのオファー：設定フェーズの Add Resource Pack
  （0x09、UUID付き）に、URLとSHA-1が **766用パック（pack_format 32、
  `detergentmc-pack-1.20.5.zip`）** のものであること。クライアントの応答
  （設定 0x06・プレイ 0x2B）はバニラのパックのUUID付きでバニラへ返されること
  （`ProxySession766Test`）
- 766用パックのzip内容：`pack.mcmeta` が `pack_format: 32` で、泡テクスチャ
  （16x16 PNG）・泡モデル・スライムボールのオーバーライドが入っていること
  （`ResourcePackBuilderTest`）
- 766用パックと763用・764用・765用パックの配信：同じ25567番ポートで4つのURLが
  200を返し、SHA-1が一致すること（`ResourcePackServerTest`、
  `ResourcePackWiringTest`）
- 766＋online-modeの認証：プロキシがMojang認証を完結させ、認証済みUUID・名前で
  内部バニラへ繋ぐこと（`ProxySession766Test.join766OnlineThroughProxyAuth`、
  偽セッションサーバーでの検証）。認証失敗時は理由付きLogin Disconnectで
  切断されること
- 765↔766対応表（逆向きは反転）と763↔766・764↔766の合成表
  （`RegistryRemapper766Test`、検証スクリプト
  `detergentmc-protocol/tools/verify-766-tables.py` 87チェックと
  `verify-reverse-tables.py`）
- 内部763サーバーの配線：`ClientProxy` が内部763で構築できること
  （`ClientProxyTest.internalProtocol763IsAccepted`）、
  `DetergentServer` が `minecraft-version: "1.20.1"` のときに内部763・
  765用パックの差し替え・763用パックのバニラ渡しをすること
  （`ServerProtocolWiringTest.clientProxyFor1201UsesInternalProtocol763And765Pack`）

### B. 実機でしか確認できない項目（この手順書の本題）

- リソースパックがクライアントの画面で「互換性あり」と表示され、実際に
  ダウンロード・適用されること（プロトコル検証では、クライアントがパックを
  受け取って適用したかどうかまでは見えない）
- 泡テクスチャが**目で見て**泡に見えること（スライムボールが泡の絵になるか）
- スポーン地点の風景・チャンク・ブロックが正しく表示されること
  （1.20.5で追加された vault・ominous 系ブロックは、古いサーバーでは
  落とされるか代替表示される。目で見て確認する）
- 次元移動（ネザー／エンド）で画面に何が起きるか（Respawn は766で
  dimension 番号のため変換する。実機で正しく切り替わるか確認する）
- レシピ帳が空になること（Declare Recipes を落としているため。実機での
  見た目を記録する）
- インベントリ操作ができるか（Window Click／Set Creative Slot は
  データコンポーネント形式のため変換できず落としている。**古いサーバーでは
  インベントリ操作ができない既知の制限**。実機でどこまで操作できるか記録する）
- online-modeでのMojang認証の成否（実アカウントが必要。下の「5. online-mode」を参照）
- 体感の遅延・切断の有無、スキンの表示、サウンドなど

## 1. 起動

### 1.1 準備（初回のみ）

```sh
cd ~/workspace/detergentmc
./gradlew build :bubbles:hello-bubble:jar
cp bubbles/hello-bubble/build/libs/hello-bubble-0.1.0-1.20.4.jar run/bubbles/
```

`run/eula.txt` と `run/vanilla/eula.txt` が `eula=true` になっていること。

### 1.2 起動（ファットjar・推奨）

```sh
java -Dfile.encoding=UTF-8 -jar build/libs/detergentmc-0.1.0-1.20.4.jar
```

Gradle経由の `./gradlew :detergentmc-core:runServer` ではコンソール入力が
届かないので、対話するなら上の `java -jar` で起動すること。

起動完了の目安：`Done (...)!` と `バニラサーバーが起動しました (ポート 25565)。`

この手順書の参加テストでは、サーバーはまず **1.20.4** のまま
（`minecraft-version: "1.20.4"`、既定）で、1.20.5／1.20.6クライアントが
プロキシ経由で参加する。サーバー自体を1.20.1／1.20.2／1.20.5／1.20.6で
動かす場合は下の「1.5 サーバーを別バージョンで動かす場合」を参照すること。

### 1.3 ポート構成

| ポート | 既定 | 役割 |
| --- | --- | --- |
| `server.port` | 25565 | プロキシの公開ポート。**クライアントは必ずここに接続する** |
| `server.internal-port` | 25566 | バニラの待ち受けポート（`127.0.0.1` のみ。直接つながないこと） |
| `resource-pack.port` | 25567 | リソースパック配信用（loopbackのみ）。765用・763用・764用・766用の4つを出す |

起動時に4つのパックが生成される：

| ファイル | 中身 |
| --- | --- |
| `run/data/resource-pack/detergentmc-pack.zip` | 765用（pack_format 22）。`server.properties` の `resource-pack` に書かれる（内部765のとき） |
| `run/data/resource-pack/detergentmc-pack-1.20.1.zip` | 763用（pack_format 15）。プロキシが763クライアントにだけ出す |
| `run/data/resource-pack/detergentmc-pack-1.20.2.zip` | 764用（pack_format 18）。プロキシが764クライアントにだけ出す |
| `run/data/resource-pack/detergentmc-pack-1.20.5.zip` | 766用（pack_format 32、1.20.5と1.20.6で共用）。プロキシが766クライアントにだけ出す |

コンソールに `リソースパックを配信しています: http://127.0.0.1:25567/detergentmc-pack.zip`
が出れば配信開始。766用パックも同じポートの
`http://127.0.0.1:25567/detergentmc-pack-1.20.5.zip` で配信される。

### 1.4 online-mode／offline-modeの切替方法

`run/detergentmc.yml` の `server.online-mode` を変える。既定は `true`
（プロキシがMojang認証を完結させる）。実機で正規アカウントを使わない
確認（オフラインの動作確認だけ）なら `false` にする。内部バニラは常に
offline-mode（信頼済み接続）で動くため、ここの切替はプロキシ認証の
オン／オフである。

```yaml
server:
  online-mode: false
```

### 1.5 サーバーを別バージョンで動かす場合

`run/detergentmc.yml` の `minecraft-version` を変えて再起動する。
内部プロトコル・データパック形式・バニラに渡すリソースパックが連動して変わる。

| `minecraft-version` | 内部プロトコル | データパック | バニラに渡すリソースパック | 注意 |
| --- | --- | --- | --- | --- |
| `1.20` / `1.20.1` | 763 | 15 | 763用（pack_format 15） | プロキシが766クライアントの設定フェーズを合成する |
| `1.20.2` | 764 | 18 | 764用（pack_format 18） | 設定フェーズは766形式へ変換して中継する |
| `1.20.3` / `1.20.4` | 765 | 26 | 765用（pack_format 22） | 既定。設定フェーズは766形式へ変換して中継する |
| `1.20.5` / `1.20.6` | 766 | 41 | 766用（pack_format 32） | **Java 21 が必要**（下の注意を参照） |

#### Java 21 の注意（1.20.5／1.20.6サーバーのときだけ）

バニラ1.20.5／1.20.6サーバーは Java 21 を要求する。DetergentMC本体は
Java 17 で動く。`VanillaServerHost` は次の順番で Java 21 を探す。

1. `detergentmc.java21.home` システムプロパティ、
2. `DETERGENTMC_JAVA21_HOME` 環境変数、
3. 現在の `java.home` が Java 21 以上のときはそれ、
4. どれも無いときは現在の Java を使うが、バニラが起動を拒否する。

ファットjarを Java 17 で起動したまま、内部だけ Java 21 にする例：

```sh
DETERGENTMC_JAVA21_HOME=$HOME/workspace/.tools/jdk-21.0.13+9 \
  java -Dfile.encoding=UTF-8 -jar build/libs/detergentmc-0.1.0-1.20.4.jar
```

ファットjar自体を Java 21 で起動してもかまいません（その場合は3. の経路）。

#### 実起動確認の記録（2026-11-09、担当2の報告）

- バニラ1.20.5サーバーが `Done (27.320s)!` まで起動した
  （DetergentMC起動から `Done` まで約56秒。初回起動でバニラjarの
  ダウンロードを含む）。起動コマンドは
  `~/workspace/.tools/jdk-21.0.13+9/bin/java -Dfile.encoding=UTF-8 -jar
  build/libs/detergentmc-0.1.0-1.20.4.jar --workdir
  /tmp/detergentmc-1205-boot`、設定は `minecraft-version: "1.20.5"`・
  ポート 26565／26566／26567・online-mode: false。
- バニラ1.20.6サーバーも同じ方法で `Done (44.823s)!` まで起動した
  （`/tmp/detergentmc-1206-boot`、DetergentMC起動から `Done` まで
  約100秒）。
- データパックは両方とも起動時に自動で読み込まれた
  （`Found new data pack file/detergentmc.zip, loading it automatically`）。
  生成された `pack.mcmeta` は `pack_format: 41`。**データパック関連の
  警告は出なかった。**
- リソースパックは両方とも `server.properties` に766用パック
  （`http://127.0.0.1:26567/detergentmc-pack-1.20.5.zip`、
  pack_format 32、SHA-1 `ce83c23f29dc2b81c6c5ab29a61cad4367f43bc0`）
  が書かれ、4パックすべて同じ26567番ポートで200を返し、SHA-1も
  一致した（1.20.5の起動時に実測）。
- 当時は `ClientProxy` が内部766を拒否して DetergentMC 本体が起動しきら
  なかったが、プロキシ担当の作業で解消済み（2026-11-09）。プロキシが
  内部766で実起動して listen することは確認済み。**ファットjar全体での
  起動しきり（プロキシ listen＋コンソール開始まで）の再確認は、実機プレイ
  テストのときに改めて行うこと。**

## 2. 参加（1.20.5／1.20.6クライアント）

1. Minecraft 1.20.5 または 1.20.6 のクライアントを起動する。
2. マルチプレイ → サーバーを追加 → アドレスに `127.0.0.1:25565`
   （`server.port` の既定。直接つなぐ内部ポート 25566 ではないこと）。
3. サーバーリストでバージョンが **1.20.5**（protocol 766）と表示されること。
4. サーバーに参加する。リソースパックのオファーが出たら承諾する
   （pack_format 32 の766用パック）。
5. スポーンしたら、チャットで何か打ってみる（バニラログに
   `<名前> メッセージ` が出ること）。

## 4. わざと失敗するはずのもの（バグではない）

- 1.20.7以降のクライアント（プロトコル767以上）はログイン時に断られる
  （「新しすぎます」）。
- 1.20.1より古いクライアント（プロトコル762以下）はログイン時に断られる
  （「古すぎます」）。
- 古いサーバー（内部763／764／765）での Window Click／Set Creative Slot は
  落とされる（上の「3.6」を参照）。バグではなく、データコンポーネント形式と
  NBT 形式の変換が未実装のため。
- 内部763／764／765のサーバーで、1.20.5以降の新ブロック（vault など）は
  表示されないか代替表示になる（対応表で落とすか近いブロックへ変えるため）。

## 付録：外部配信（`resource-pack.url-766` / `sha1-766`）の設計

766用パックを外部HTTPSで配信するときは、`detergentmc.yml` の
`resource-pack.url-766` / `sha1-766` に766用パックのURLとSHA-1を書く
（任意・未指定時は765用パックを出す。無効なときは警告ログ＋765用パックへ
フォールバックし、起動は止めない。763／764用と同一方針）。
公開HTTPSの置き場は2026-11-09時点で未定のため、既定はloopback配信。
