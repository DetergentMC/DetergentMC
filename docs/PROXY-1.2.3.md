# プロトコル28（Minecraft 1.2.1〜1.2.3）対応ノート

DetergentMC のレガシーフロントエンド（`detergentmc-legacy-frontend`）がプロトコル28
（**1.2.1／1.2.2／1.2.3**）を受けられるようにした記録。Stage A の実測が正であり、
本文書の数値はすべて実 jar・実バニラからの採取に基づく。

番号対応：**28 ＝ 1.2.1／1.2.2／1.2.3**（先行調査 `legacy-prep-final/PREP-FINAL.md`
のログイン探査で実測）。流布している表の「28 ＝ 1.2.4」は誤りで、
**1.2.4 はプロトコル29**である（本書の Stage A でも再検証した。
1.2.4 は 29 の実装がそのままカバーする。`docs/PROXY-1.2.5.md` の
1.2.4 節も参照）。28 は Netty 以前世代の番号であり、legacy モジュール内にのみ置き、
`ProtocolVersion` には入れない。

実サーバー jar の入手経路：piston-meta は 1.2.4 以下のサーバー jar を配布して
いないため、Minecraft Wiki の各バージョンページから辿れる Omniarchive Vault の
jar を使い、公式 .exe 配布物（PE スタブ 180,736 バイト＋jar）とバイト単位で
一致することを確認して真正性を担保した（先行調査）。

## Stage A：実測（1.2.3／1.2.2／1.2.1 サーバー jar、JDK 8）

- バニラサーバー jar SHA-1（ディスクで再検証済み）：
  - 1.2.3 `d0e0dab53361e16e154f5b6cba2a7d8e4323fb8e`
  - 1.2.2 `673f50223b363c4c474d520c99104bd8481f0ce6`
  - 1.2.1 `50bbca507680a248c4d8e965c800593dc5853026`
  - （参考）1.2.4 `ab5203296605bdb3a020b8b4ea6c8d03fd3a3e66`
- パケット登録は各 jar から機械抽出（1.2.3 の基底クラス `lv`）。
  **登録 67 件**（29 は 68 件）。**1.2.3⇔1.2.2⇔1.2.1 は登録・
  ワイヤ形式・レジストリとも差分ゼロ**（3 本とも同一の表でカバーする）。
- **29⇔28 の差分は 1 件だけ**：
  - **0xCA player_abilities が 29 にだけある**（BOOL×4 形も 29 と同一の
    ものが 1.2.4 で導入された）。28 側にこのパケットは存在しないため、
    28 向けには能力パケットを送らない（落とす）。
  - 残り 67 件は方向フラグ・読み書き形式とも**バイト単位で同一**
    （機械抽出の全件比較で確認）。ログイン形式も 29 と同一形
    （[protocol I32, ユーザー名, levelType, gamemode I32, dimension I32,
    difficulty U8, worldHeight U8, maxPlayers U8]、応答も同形）。
    スロットの条件付き NBT（ダメージ可能アイテムのみ NBT）も、
    DataWatcher の素スロット形（型 0〜6、型 5 は id／個数／ダメージのみ）も
    29 と同一。
- **29⇔1.2.4 は差分ゼロ**：登録 68 件・全パケットの読み書き形式・
  方向フラグ・ブロック／アイテムレジストリ（124 種／141 種）・
  ダメージ可能集合（49 件）すべて同一。1.2.4 向けに新規プロトコルは
  作らず、29 のカバー範囲に 1.2.4 の名前を加える。
- レジストリ（実 jar のランタイム反射で抽出）：
  - ブロック 124 種、アイテム 141 種——29／1.2.4 と完全同一。
  - ダメージ可能アイテム集合は **49 件**で 29 と同一
    （`LegacyWire.DAMAGEABLE_ITEMS_1_2_5` と集合として一致することを
    実測で確認。なお PROXY-1.2.5.md 本文の「51 件」は数え間違いで、
    実 jar の述語 `maxDamage > 0 && !hasSubtypes` の実測は 49 件）。
  - エンティティ登録も 29 と完全同一（オブジェクト 16 投げポーション、
    17 経験値ボトル、モブ 98 ヤマネコ、99 アイアンゴーレムを含む）。
- 採取による裏付け（実バニラを JDK 8 で起動し平文ログイン）：
  - 先行調査の採取（1.2.3: 341 パケット、1.2.2: 380 パケット、
    1.2.1: 231 パケット、1.2.4: 328 パケット）を抽出表で
    最後まで解析し、ズレゼロを確認。
  - 本 Stage A の自前採取（1.2.3: 419 パケット）も同様にズレゼロ。
  - ログイン応答の実測値：[entityId, "", "flat", gamemode 0,
    dimension 0, difficulty 1, worldHeight 0, maxPlayers 20]
    （29 と同じ値の並び）。

## 近似・落とすもの（28 向け）

- **0xCA player_abilities を落とす**：28 にパケット自体が無い。
  能力（飛行可否・クリエイティブ等）は 28 のクライアントでは
  ゲームモード（ログイン／リスポーン）からのみ決まる。
- それ以外の近似は 29 の層をそのまま継承する（29 向けの近似表は
  `docs/PROXY-1.2.5.md` を参照）。28 のレジストリは 29 と同一なので、
  ブロック／アイテム／エンティティの追加近似は無い。

## Stage B〜D：実装

- パケット表：`LegacyPacketTable` の V1_2_3 は V1_2_5 の表から
  0xCA を除いたもので構成（差分 1 件をテストで固定）。
  変換器・チャンク再配置は 29 の経路をそのまま使う
  （`LegacyChunkRemap` の 28 層は 29 層への全面委譲）。
- ログイン：29 と同じ平文経路（`LegacySession` の平文判定は
  {29, 28, 23, 22} に一般化され、ログイン 0x01 のプロトコル番号で
  世代を確定する）。ダイレクトモードの不一致キックはバニラ同様
  「Outdated client!／Outdated server!」。
- アダプタ：`V1_2_3Adapter`（代表）＋ `V1_2_2Adapter`／
  `V1_2_1Adapter`（副、プロトコル28）＋ `V1_2_4Adapter`
  （副、プロトコル29）を ServiceLoader 登録。コア配線
  （`minecraft-version` 名、内部バニラ Java 8、versionedJars）も
  1.2.1〜1.2.4 まで追加済み。
- jar の注意：piston-meta に 1.2.4 以下の配布が無いため、実行時の
  自動ダウンロードは効かない。バニラ jar は手動配置が必要
  （SHA-1 は本書 Stage A の記載どおり）。
- **Stage E（実バニラ統合テスト）は完了**（2026-11-20、下記
  Stage E 節）。残る未確認は本物のゲームクライアントでの
  確認のみ。

## Stage E（実バニラ統合）完了（2026-11-20）

29 の Stage E 最終 HEAD `71c2370` へリベースし、新規セルを
追加した（28／23／22 合計 12 件、各世代：ブリッジ→実バニラ
1.7.10、ダイレクト→自世代の実バニラ、§1 ピング完全形、
素の FE 01 への旧形式応答）。28 のセルは：ブリッジ fake28 →
実バニラ 1.7.10、ダイレクト fake28 → 実バニラ 1.2.3
（平文ログイン、jar は Omniarchive 経由で入手し公式 .exe と
バイト一致を確認した手動配置、SHA-1
`d0e0dab53361e16e154f5b6cba2a7d8e4323fb8e`）、§1 ピング
完全形（28／"1.2.3"）、素の FE 01 への旧形式応答。
参加系はすべて「参加→チャット→Keep Alive 応答→応答後の
2 通目のチャット到達」を実バニラのログで確認した。
回帰 115 セル（29 の Stage E の全セル）と合わせて
**統合 127 セルすべて合格**、分割検証は **4,998 件・
合格 4,981・失敗 0・スキップ 17**、最終監査（全単体
クラスの XML 実在＋統合 127 セルのメソッド名一致）も合格。

リベース時の注意点（重複解消）：競合は LegacyProtocol の
版名対応スイッチ（土台側の "1.2.4" → 29 と 28 側の
1.2.3／1.1／1.0.0 追加を両方保持）、ServiceLoader 登録
ファイル（両側保持、`V1_2_4Adapter` は 1 つだけ）、
docs 3 件（29 の Stage E 記述を保持し 28 節を追加）。
さらに自動マージで競合マーカーが残った 3 ファイル
（VanillaServerHost の Java 8 対象一覧、LegacyWiringTest、
core の build.gradle）は上位集合として解消し、両系統が
追加した同一テスト `adapter124IsDiscoverable` の重複は
1 つに統合した。1.2.4 のカバーは最終的に正しい実装が
1 つだけ残っている（版名対応・サービス登録・配線テスト
とも単一）。
