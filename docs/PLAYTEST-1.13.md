## 0. この手順書の読み方

DetergentMC の 393 対応は、Stage E（実バニラ統合テスト＋
分割検証）まで完了した（総数 3,871 件・失敗 0、統合セルは
新規3件＋回帰35件の計38件がすべて成功）。残るのは
本物のゲームクライアントでの確認のみで、このチェックリストで
実機確認する。

393 は 401（1.13.1）とパケット ID が完全一致し、形式差分は
edit_book の `hand` だけだが、**レジストリ（サンゴまわり）が
違う**。実機では特にサンゴとインベントリ（旧形式 slot）の
見た目・挙動が重点になる。

### A. 単体テストで検証済みの項目（実機では再現の確認）

- 393 のパケット ID 表が 401 と全件一致すること、bed が
  393／401／404 にだけ存在すること（`PacketIds393Test`）。
- ブロック／アイテム変換表 35,350 件の全件照合
  （`tools/verify-393-tables.py`）。サンゴの対応は
  `RegistryRemapper393Test` と `ProxySession393Test`
  （404 サーバーの Set Slot のアイテム 447 が 393 クライアントで
  旧形式 438 になる等）で固定済み。
- チャンクの 393 変換（tube_coral を含むパレット）と比較
  （`ChunkTranslator393Test`、`BedrockChunkTranslator393Test`）。
- 393 用リソースパック（pack_format 4、
  `detergentmc-pack-1.13.zip`）の生成と配信、393 パックが無い
  構成での 401 パック代替（`ResourcePack*393Test`）。
- 対応クライアント一覧の最古が 393 で、401／404 が脱落して
  いないこと（`ClientAdapter393Test`）。

### B. 実機でしか分からない項目

- [ ] 本物の 1.13 クライアントで内部 393／401／404／758 サーバーへ
      参加し、地形・ブロックの見た目が崩れていないか。
- [ ] **サンゴの見た目**：サンゴ礁で生きたサンゴ・サンゴブロックが
      正しく表示されるか。新しいサーバー側で dead coral を置いた
      とき、393 クライアントで対応する生きた coral に見えるか
      （仕様どおりの近似か、違和感がないか）。
- [ ] **インベントリ／スロット**：393 は旧形式 slot（i16）。
      アイテムの出し入れ、Window Click、Set Creative Slot が
      実機で正しく動くか（401 のプレイテストと同重点）。
- [ ] **本の編集・署名**：393 の edit_book には末尾の hand が無い。
      本を書いて署名する操作が実機で完結するか。
- [ ] **自然地形のブロック精度**：パレットが大きくビット幅が
      5 以上になるセクションでブロックが化けていないか
      （crossing 詰めの確認）。
- [ ] **チャンクの明るさ**：光はチャンク内蔵。新しいサーバー
      （758 等）から来たとき、暗転・明るさの段差が無いか。
- [ ] **エンティティのスポーン**：ボート等のオブジェクト系と
      生物系（Spawn Entity Living）の振り分けが実機で正しいか。
- [ ] **2人プレイでの相互表示**：フェイククライアントでは
      確認できない最重要項目。2つの本物クライアントで互いの
      姿・移動・設置ブロックが見えるか。
