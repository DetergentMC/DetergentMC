# DetergentMC 1.12.1 実機プレイテスト — チェックリスト

2026-11-18 作成、Stage E 完了に合わせて確定。1.12.1 クライアント
（プロトコル338）で各サーバーに参加する実機確認のための手順と、
結果の記録用。詳細な仕組みは `docs/PROXY-1.12.1.md` を参照。

## 0. この手順書の読み方

DetergentMC の 338 対応は Stage A〜E まで完了し、分割検証
（3,893 件・失敗 0）と実バニラ統合テスト（338 セル 3 件＋
回帰 41 件＝44 セル全合格）で確認済み。統合セルでは参加→
チャット→Keep Alive の往復→2 通目のチャット到達までを
実ワイヤで確認した。ただし**本物のゲームクライアントでの
確認は未実施**。このチェックリストはその実機確認のための
ものである。

338 は 340（1.12.2）とワイヤ形式がほぼ完全同一で、唯一の差分は
**Keep Alive の keepAliveId が varint**（340 以降は i64）。
実機では特に **Keep Alive の往復（切断されずに長時間遊べるか）**
が重点になる。それ以外の見え方は 340 のプレイテスト
（PLAYTEST-1.12.2.md）と共通の観点でよい。

### A. 単体テストで検証済みの項目（実機では再現の確認）

- 338 のパケット ID 表が 340 と全件一致すること
  （`PacketIds338Test`：全282エントリで id338==id340 を照合、
  存在 120 件）。
- 対応クライアント一覧の最古が 338 で、340／393／401／404 が
  一覧に残ること（`ClientAdapter338Test`）。
- 758 サーバーの Set Slot（salmon）が 338 クライアントで
  fish＋itemDamage 1 になること（340 経路の共用、
  `ProxySession338Test`）。
- Keep Alive の付け替え往復：758 サーバーの i64 ID が 338
  クライアントへ varint で届き、応答が i64 に戻ること。
  int 範囲を超える ID（例：0x1_2345_6789）は切り捨てて送り、
  応答で元の値へ復元されること。内部 338 サーバーの varint ID が
  763 クライアントへ i64 で届き、応答が varint に戻ること
  （いずれも `ProxySession338Test`）。
- 実バニラ統合（Stage E）：fake338→実 1.12.1、fake338→実 1.12.2、
  fake340→実 1.12.1 の 3 セルで、参加・チャット・Keep Alive の
  往復・応答後の 2 通目のチャット到達まで実ワイヤで確認済み
  （`ProxyIntegrationTest`、回帰 41 セルと合わせて 44 セル全合格）。
- 338 用リソースパック（pack_format 3、旧レイアウト、
  `detergentmc-pack-1.12.1.zip`）の生成と配信、338 パックが
  無い構成での 340 パック代替（`ResourcePack*338Test`）。
- Bedrock→338 のチャンク変換と生物スポーン（340 の専用パースを
  共用、498 の関数には流さない。`BedrockChunkTranslator338Test`、
  `JavaBackendConnection338Test`）。

### B. 実機で重点的に見てほしい項目

1. **長時間セッションの安定性**：338 クライアントで他バージョン
   サーバー（特に 758 以降）に30分以上接続し続け、Keep Alive の
   タイムアウトで切断されないか。サーバー側の Keep Alive ID は
   ランダムな long 値のため、切り捨て＋復元が毎回働く前提で
   確認する。
2. **338 サーバーへの接続**：他バージョンクライアント
   （763 等）で内部 1.12.1 サーバーに入り、Keep Alive 応答が
   varint で正しく戻り切断されないか。
3. **340 との相互運用**：338 クライアント→1.12.2 サーバー、
   340 クライアント→1.12.1 サーバーで、参加・移動・チャット・
   インベントリ操作が問題ないか。
4. 340 と共通の観点：ブロックの意味対応（色物ブロック）、
   インベントリの Damage 付け替え（魚・ベッド・バナー等）、
   チャンクの見え方（直接パレット13ビット）。
5. 2人以上での相互表示（Player Info／スポーン）が見えるか
   （全バージョン共通の最優先確認項目）。
6. リソースパックの提示：338 クライアントに 1.12.1 用パックが
   提示され、適用されるか。338 パックを外した構成では 340
   パックが代替で提示されるか。

### C. 既知の制限（実機でも再現する想定のもの）

- データパックが無い世代のため、trigger ブリッジ
  （/trigger d_hello 等の言語切替・hello）は 338 バックエンドでは
  使えない（340 から引き継ぐ既知の課題、代替は未定）。
- レシピ系パケットと Statistics は落とす設計。
- スポーンエッグの EntityTag は運ばない（pig 近似）。
  ベッド／バナー／頭は代表色・代表種への近似。anvil の facing は近似。
