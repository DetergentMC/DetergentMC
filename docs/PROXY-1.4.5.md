# プロトコル49（Minecraft 1.4.5／1.4.4）対応ノート

DetergentMC のレガシーフロントエンド（`detergentmc-legacy-frontend`）がプロトコル49
（**1.4.5 と 1.4.4**）を受けられるようにした記録。Stage A の実測が正であり、
本文書の数値はすべて実 jar・実バニラからの採取に基づく。

⚠️ **番号対応の訂正**：流布している対応表では 49 と 51 の帰属が逆に書かれていることが
多い（49＝1.4.6/1.4.7、51＝1.4.4/1.4.5）。先行調査（`legacy-prep-old/PREP-OLD.md`）の
レガシーピング §1 実測では **49＝1.4.5／1.4.4、51＝1.4.7／1.4.6** が正しい。
本実装・本文書は実測値を採用する。

## Stage A：実測（1.4.5 サーバー jar、JDK 8）

- バニラ 1.4.5 サーバー jar SHA-1 `c12fd88a8233d2c517dbc8196ba2ae855f4d36ea`
  （piston-meta 照合済み）。1.4.4 サーバー jar SHA-1
  `4215dcadb706508bf9d6d64209a0080b9cee9e71`。
- パケット登録は jar から機械抽出（基底クラス `eg`）。**登録 75 件**。
- 51⇔49 の差分は次のとおり（51＝1.4.7 の機械抽出との全件比較）。
  61⇔51 の差分より小さいが、ゼロではない：
  1. **49 のみに存在するパケットが 1 件**：0x15 pickup_spawn
     （[I32 entityId, SLOT, I32 x, I32 y, I32 z, I8 yaw, I8 pitch, I8 roll]、
     サーバー→クライアントのみ）。落ちたアイテムのスポーン専用パケットで、
     51 では廃止され 0x17 spawn_object の種別 2 に統合された。
  2. **形式差 2 件**：
     - 0x17 spawn_object：49 には pitch／yaw の 2 バイトが無い
       （[I32, U8, I32, I32, I32, I32 data, I16×3 速度]。回転バイトは 51 で追加）。
     - 0x38 chunk_bulk：**49 には skyLight フラグが無い**
       （[I16 件数, I32 長, データ, チャンクごと I32/I32/I16/I16]）。
       フラグは 51 から。prep の「skyLight フラグは 51〜78」を実測で裏付けた
       （49 は範囲外）。ペイロード内の空光配列の有無は次元から決まる
       （1.4.5 の実バルクでサイズ検算済み）。
  3. **方向フラグ差 1 件**：0x10 held_item_change は 49 では
     クライアント→サーバーのみ（51 では双方向）。
  4. それ以外は 51 とバイト単位で同形：open_window の useTitle 無し、
     体力 I16、能力速度バイト、DataWatcher 7 型、スロットの gzip NBT も
     すべて 49 にすでに存在する。
- レジストリ差分（両 jar の Block/Item 登録名対応とエンティティ登録の機械比較）：
  - **ブロックは完全同一**（登録名 121 件、差分なし）。
  - **1.4.6 で追加されたアイテムは 3 件**：401 花火（fireworks）、
    402 花火の星（fireworksCharge）、403 エンチャントの本（enchantedBook）。
    削除は無し。
  - エンティティは **花火ロケット（オブジェクト種別 22）が 51 のみ**。
    モブ種別に変化なし。
- **1.4.4 は差分ゼロ**：1.4.4 jar の機械抽出でも登録 75 件・ID 集合一致・
  スキーマ差分 0 件、Block/Item 登録名対応とエンティティ登録も完全一致。
  よってプロトコル49 は 1.4.5 と 1.4.4 の両方を 1 つの表でカバーする。
- 実ワイヤ採取（実バニラ 1.4.5、暗号化ログイン＋歩行＋チャット）：
  111 パケットを末尾までズレなく解析。チャンクバルク 34 件
  （チャンク 169 個、全バルクで膨張後サイズが
  Σ（セクション数×10240＋追加配列×2048＋256）と一致＝空光配列は
  ペイロードに含まれ、フラグバイトはワイヤに無いことを確認）。
  チャットはサーバーログに到達。プロトコルエラー・切断なし。
- pack_format の概念はこの世代に無い（テクスチャパック）。
  DataVersion の概念も無い。

## 近似・落とすもの（49 向け）

- 1.4.6 追加アイテム（51 層の後に適用）：花火→紙（401→339、
  花火の主材料）、花火の星→グローストーンダスト（402→348、
  星の火花材料）、エンチャントの本→本（403→340）。
  ブロックは 51 と完全同一なので、ブロック近似は 51 層を
  そのまま使う。
- 花火ロケットのスポーン（オブジェクト種別 22）は 49 に
  存在しないため落とす（2 秒程度の視覚エンティティ）。
- 0x17 は専用コーデック `spawn_object_norot`（回転バイト
  無し）。内部形式の pitch／yaw は 49 向けには書かず、
  49 から読むときは 0 を補う。
- 0x38 は専用コーデック `chunk_bulk_nosky`（フラグ無し）。
  ブリッジでは現代側の sky 値をペイロードのレイアウト
  判定にだけ使い、ワイヤには書かない（1.4.5 クライアントは
  次元から空光の有無を判断する）。
- アイテムエンティティのスポーンは、ブリッジでは現代側の
  0x17 種別 2 をそのまま 49 の 0x17 で送る（スタックは
  後続のメタデータで届く）。実バニラ 1.4.5 サーバーが使う
  0x15 はダイレクトモードでそのまま中継する。**1.4.5
  クライアントが 0x17 種別 2 を受けられるかは実機未確認**
  （クライアント側ハンドラはサーバー jar に含まれないため
  採取でも確認できない。PLAYTEST-1.4.5.md の重点項目）。
- 51 世代と共通の制限はそのまま継承する：スコアボードと
  名前付きパーティクルは無い、体力は I16 へ丸め、能力速度は
  バイト量子化、馬はブタ、属性／乗り物操作は無い。

## 実装（Stage B〜D、2026-11-20）

- `LegacyProtocol`：V1_4_5（=49）を追加。対応一覧は
  [78, 74, 73, 61, 60, 51, 49]。`is1_4Generation` は
  51 と 49 の両方を含むよう拡張した（ブロック近似・
  トロッコ変種・1.5 世代共通のワイヤ特性は 49 でも
  そのまま効く）。
- `LegacyPacketTable.V1_4_5` は 51 の表から作る実体マップ
  （75 件）：0x15 pickup_spawn を専用コーデック
  `pickup_spawn` で追加、0x17 は `spawn_object_norot`、
  0x38 は `chunk_bulk_nosky` に差し替え、0x10 は
  サーバー行きのみの方向フラグに直した。
- コーデック：`spawn_object_norot` は回転バイトを読み書き
  しない（フィールド列の形は spawn_object と揃え、読みでは
  0 を補う）。`chunk_bulk_nosky` はフラグバイトを読み書き
  しない（skyLight フィールドは意味を持たないプレース
  ホルダとして false を返す）。`pickup_spawn` は
  [entityId, スロット, x, y, z, yaw, pitch, roll] を
  そのまま読み書きする。
- 変換器（`LegacyPlayTranslator`）の 49 向け処理：
  スロットは 49 向け近似表（51 層＋花火系 3 件）、
  花火ロケット（オブジェクト種別 22）のスポーンは落とす。
  ブロック近似は 51 と完全同一（レジストリ実測）なので
  `LegacyChunkRemap` の 51 層へ全面委譲し、49 層は
  アイテム 3 件だけを持つ。
- ダイレクトモード・アダプタ（`V1_4_5Adapter` と
  `V1_4_4Adapter` の両名、ブロック集合は代表集合内では
  1.4.7 と同じ）・Java 8 配線・versionedJars は 51 と
  同じ形で追加。
- 単体テスト：レガシーモジュール 150 件を含む分割検証を
  実施（集計は split-verification-49/ と Stage D コミットを
  参照）。
