# DetergentMC 1.12 実機プレイテスト — チェックリスト

2026-11-18 作成、Stage E 完了に合わせて確定。1.12 クライアント
（プロトコル335）で各サーバーに参加する実機確認のための手順と、
結果の記録用。詳細な仕組みは `docs/PROXY-1.12.md` を参照。

## 0. この手順書の読み方

DetergentMC の 335 対応は Stage A〜E まで完了し、分割検証
（3,944 件・失敗 0）と実バニラ統合テスト（335 セル 3 件＋
回帰 44 件＝47 セル全合格）で確認済み。統合セルのうち
fake335 の 2 件では参加→チャット→Keep Alive の往復→
2 通目のチャット到達までを実ワイヤで確認した。ただし
**本物のゲームクライアントでの確認は未実施**。この
チェックリストはその実機確認のためのものである。335 は
この降下（578→335）の最終バージョンである。

335 は 338（1.12.1）／340（1.12.2）とワイヤ形式が完全同一だが、
**パケットIDが 338 と 53 件ずれる**（レシピブック再編：
prepare_crafting_grid が 335 のみにあり、craft_recipe_request／
response は 338 以降）。実機では特に、**ID の付け替えが効く
パケット全般の見え方**（0x2b 以上のクライアント行きパケット、
0x01〜0x11 のサーバー行きパケット）と、338 と共通の
**Keep Alive の往復（切断されずに長時間遊べるか）**が重点になる。

### A. 単体テストで検証済みの項目（実機では再現の確認）

- 335 のパケット ID 表が機械的規則どおり 338 とずれること
  （`PacketIds335Test`：全283エントリで規則を照合、存在 119 件）。
- 対応クライアント一覧の最古が 335 で、338／340／393／401／404 が
  一覧に残ること（`ClientAdapter335Test`）。
- 758 サーバーの Set Slot（salmon）が 335 クライアントで
  fish＋itemDamage 1 になること（340 経路の共用、
  `ProxySession335Test`）。
- クライアント行き ID の付け替え：758 サーバーの Update Time が
  335 クライアントへ 0x46（340 では 0x47）で届くこと。
  内部 335 サーバーの Update Time（0x46）が 763 クライアントへ
  763 の ID で届くこと（いずれも `ProxySession335Test`）。
- Keep Alive の付け替え往復：758 サーバーの i64 ID が 335
  クライアントへ varint で届き、応答（ワイヤID 0x0C）が i64 に
  戻ること。int 範囲を超える ID（例：0x1_2345_6789）は切り捨てて
  送り、応答で元の値へ復元されること。内部 335 サーバーの
  varint ID が 763 クライアントへ i64 で届き、応答が varint
  （0x0C）に戻ること（いずれも `ProxySession335Test`）。
- Prepare Crafting Grid（335 のみ、サーバー行き 0x01）が
  落とされること。Craft Recipe Response が 335 クライアントに
  届かないこと（`ProxySession335Test`）。
- 335 用リソースパック（pack_format 3、旧レイアウト、
  `detergentmc-pack-1.12.zip`）の生成と配信、335 パックが
  無い構成での 338 パック代替（`ResourcePack*335Test`）。
- Bedrock→335 のチャンク変換と生物スポーン（340 の専用パースを
  共用、498 の関数には流さない。`BedrockChunkTranslator335Test`、
  `JavaBackendConnection335Test`）。

### B. 実機で重点的に見てほしい項目

1. **長時間セッションの安定性**：335 クライアントで他バージョン
   サーバー（特に 758 以降）に30分以上接続し続け、Keep Alive の
   タイムアウトで切断されないか（338 と同じ観点）。
2. **335 サーバーへの接続**：他バージョンクライアント
   （763 等）で内部 1.12 サーバーに入り、Keep Alive 応答が
   varint で正しく戻り切断されないか。
3. **338／340 との相互運用**：335 クライアント→1.12.1／1.12.2
   サーバー、338／340 クライアント→1.12 サーバーで、参加・
   移動・チャット・インベントリ操作が問題ないか。特に
   ID がずれる範囲のパケット（タブ補完・チャット・エフェクト・
   進捗・プレイヤー情報）の見え方を確認する。
4. **レシピブックまわり**：335 クライアントで作業台を開いたとき、
   レシピブック再編の差（Prepare Crafting Grid の破棄、
   Craft Recipe Response が来ないこと）で画面が壊れたり
   切断されたりしないか。
5. 340 と共通の観点：ブロックの意味対応（色物ブロック）、
   インベントリの Damage 付け替え（魚・ベッド・バナー等）、
   チャンクの見え方（直接パレット13ビット）。
6. 2人以上での相互表示（Player Info／スポーン）が見えるか
   （全バージョン共通の最優先確認項目）。
7. リソースパックの提示：335 クライアントに 1.12 用パックが
   提示され、適用されるか。335 パックを外した構成では 338
   パックが代替で提示されるか。

### C. 既知の制限（実機でも再現する想定のもの）

- データパックが無い世代のため、trigger ブリッジ
  （/trigger d_hello 等の言語切替・hello）は 335 バックエンドでは
  使えない（340／338 から引き継ぐ既知の課題、代替は未定）。
- レシピ系パケットと Statistics は落とす設計。335 専用の
  Prepare Crafting Grid も落とす（338 以降に届け先が無いため）。
- スポーンエッグの EntityTag は運ばない（pig 近似）。
  ベッド／バナー／頭は代表色・代表種への近似。anvil の facing は近似。
