# プロトコル22（Minecraft 1.0.0）対応ノート

DetergentMC のレガシーフロントエンド（`detergentmc-legacy-frontend`）がプロトコル22
（**1.0.0**）を受けられるようにした記録。Stage A の実測が正であり、
本文書の数値はすべて実 jar・実バニラからの採取に基づく。

番号対応：**22 ＝ 1.0.0**（先行調査 `legacy-prep-final/PREP-FINAL.md` の
ログイン探査＋jar 内定数の二重確認で実測。これが DetergentMC の対応範囲の
最古＝目標の 1.0 である）。22 は Netty 以前世代の番号であり、
legacy モジュール内にのみ置き、`ProtocolVersion` には入れない。

実サーバー jar の入手経路は 28 と同じ（Omniarchive Vault の jar を
公式 .exe 配布物とバイト単位で照合済み）。

## Stage A：実測（1.0.0 サーバー jar、JDK 8）

- バニラ 1.0.0 サーバー jar SHA-1 `38cafa1bf1e927c5cdb4cfb8cc6a34dfdcfab2b8`
  （ディスクで再検証済み）。
- パケット登録は jar から機械抽出（基底クラス `ka`）。**登録 65 件**
  （23 も 65 件）。方向フラグは共通パケットすべてで 23 と同一。
- **23⇔22 の差分**：共通 64 件、形式差分 2 件、それぞれにだけある
  パケットが 1 件ずつ。
  - **形式差分 2 件**（どちらも文字列 1 本の削除）：
    1. **0x01 login から levelType が消える**：[protocol I32,
       ユーザー名 STRING, **seed I64**, gamemode I32, dimension I8,
       difficulty I8, worldHeight I8, maxPlayers I8]（応答も同形）。
       ログインクラス `na` の読み書きと、応答構築時の seed の
       受け渡し（ワールドのシード）で確認。
    2. **0x09 respawn から levelType が消える**：[dimension I8,
       difficulty I8, gamemode I8, worldHeight I16, **seed I64**]。
  - **23 にだけある**：0xFA plugin_message（1.1 の追加。
    22 にはプラグインメッセージの仕組み自体が無いため、
    22 向けのプラグインメッセージと MC|RPack は両方向とも落とす）。
  - **22 にだけある**：**0x1B player_input** [strafe F32, forward F32,
    pitch F32, yaw F32, jumping BOOL, sneaking BOOL]（サーバーbound
    のみ、クラス `ke`＝Packet27Input 相当）。プレイヤーの移動入力
    そのもので、ハンドラはプレイヤーへ入力として渡す。
    1.1 で削除されたパケットで、現代側に対応物が無いため
    ブリッジモードでは読み捨てる（スニーク状態自体は 0x13
    entity_action でも届く）。ダイレクトモードでは素通しされる。
  - 0x33 chunk_data は 23 と同じキューボイド形式（チャンククラス
    `kr` のレイアウト・インデックス順も同一）。0x17 spawn_object も
    23 と同じ形（クラス `jd`）。
- レジストリ（実 jar のランタイム反射で抽出）：
  - ブロック 122 種：23 と完全同一。
  - アイテム 138 種：23 から **383（スポーンエッグ）が無い**
    （1.1 の追加）。
  - ダメージ可能アイテム集合は **49 件**で 23／28／29 と完全同一。
  - エンティティ登録も 23 と完全同一（差分ゼロ）。
  - スロット形式・DataWatcher（クラス `ei`、型 0〜6、型 5 は
    NBT 無しの素スロット）も 23 と同一。
- 採取による裏付け（実バニラを JDK 8 で起動し平文ログイン）：
  - 先行調査の採取（6,272 パケット）を抽出表で最後まで解析し
    ズレゼロ。
  - 本 Stage A の自前採取（3,998 パケット／155,679 バイト、
    0x1B player_input の受信を含む）もズレゼロ。
  - 1.0.0 のサーバーはログイン直後から部分キューボイド
    （例：13×10×8 のような任意サイズ）を送ってくることを確認
    （1.1 はログイン後に全面コラムを送る。キューボイド形式は
    任意の開始位置・サイズを許す設計で、ブリッジ側の生成も
    この前提で作る）。
  - ログイン応答の実測値：[entityId, "", seed, gamemode 0,
    dimension 0, difficulty 1, worldHeight 128, maxPlayers 20]
    （levelType が無いこと以外は 23 と同じ値の並び）。

## 近似・落とすもの（22 向け）

- **スポーンエッグ（383）→ 紙（339）**：22 の層で寄せる
  （それ以外は 23 の層を継承する）。
- **プラグインメッセージ（0xFA）は両方向とも落とす**：
  パケット自体が無い。テクスチャパック提示（MC|RPack）も
  当然送れない。
- **0x1B player_input はブリッジモードでは読み捨てる**
  （現代側に対応物が無い入力パケット。移動自体は位置パケットで
  届くためプレイには影響しない）。
- それ以外の近似（ランプ→グロウストーン、経験値ボトル→
  ポーション、ファイヤーチャージ→火打石と打ち金、ヤマネコ／
  ゴーレム→ブタ、チャンクの高さ 128 まで、seed 0 等）は
  23 の層をそのまま継承する（`docs/PROXY-1.1.md` を参照）。

## Stage B〜D：実装

- パケット表：`LegacyPacketTable` の V1_0 は V1_1 から 0xFA を
  除き、0x01／0x09 を文字列無し形に差し替え、0x1B player_input
  （サーバーbound のみ）を加えて構成（差分をテストで固定）。
  4⇔5 型の「23 へ全面委譲＋付け替え」で、変換器・チャンク
  キューボイド変換は 23 の経路を共用する。
- ログイン：平文経路（29／28／23 と共用）。ブリッジのログイン
  応答は 8 フィールド形（seed 0、高さ 128、levelType 無し）。
- アダプタ：`V1_0_0Adapter` を ServiceLoader 登録。コア配線
  （`minecraft-version: 1.0.0`、内部バニラ Java 8、versionedJars）
  も追加済み。jar は piston-meta に配布が無いため手動配置が
  必要（SHA-1 は本書 Stage A の記載どおり）。
- **Stage E（実バニラ統合テスト）は完了**（2026-11-20、下記
  Stage E 節）。残る未確認は本物のゲームクライアントでの
  確認のみ（`docs/PLAYTEST-1.0.md` を参照）。

## Stage E（実バニラ統合）完了（2026-11-20）

29 の Stage E 最終 HEAD `71c2370` へリベースし、新規セルを
追加した（28／23／22 合計 12 件）。22 のセルは：ブリッジ
fake22 → 実バニラ 1.7.10、ダイレクト fake22 → 実バニラ
1.0.0（平文ログイン、jar は手動配置、SHA-1
`38cafa1bf1e927c5cdb4cfb8cc6a34dfdcfab2b8`）、§1 ピング
完全形（22／"1.0.0"）、素の FE 01 への旧形式応答。
参加系はすべて「参加→チャット→Keep Alive 応答→応答後の
2 通目のチャット到達」を実バニラのログで確認した。
22 もチャンクはキューボイド形式で、ダイレクトセルでは
ログイン直後のキューボイドチャンク群をフロントエンド
越しに読み切ってから Keep Alive に到達しており、チャンク
到達と無切断も裏付けられた。回帰 115 セルと合わせて
**統合 127 セルすべて合格**、分割検証は **4,998 件・
合格 4,981・失敗 0・スキップ 17**、最終監査も合格。
リベースの競合と重複解消の経緯は docs/PROXY-1.2.3.md の
Stage E 節を参照。

1.0.0 のログ形式も実バニラの server.log で実測確認した：
起動完了行は `Done (…ns)! For help, type "help" or "?"`
の形で VanillaLogParser の ServerReady 判定がそのまま
効き、参加行は名前とアドレスの間に空白がある 1.2 世代と
同じ形で、パーサー変更なしに参加・チャットを読み取れた
（ダイレクトセルが実証）。

**Stage E で見つけた実バグ：なし**（22 の経路は実バニラ
相手に初回から全て動作）。

これでレガシー世代（78〜22 の 13 プロトコル）の Stage E は
全て完了し、Netty 世代 43 プロトコルと合わせて DetergentMC の
実装＋実バニラ統合検証が 1.0〜26.2 の全製品版で揃った。
本物の 1.0.0 ゲームクライアントでの確認は未実施。
ブリッジモードでアイテム実体を 0x17 種別 2 で送る方式の
実クライアント受け可否も未確認のまま
（`docs/PLAYTEST-1.0.md` の最重点項目）。22 では
プラグインメッセージ自体が無い（0xFA は 1.1 の追加）ため、
チャンネル経由の連携は使えない（A〜D 時点の制限のまま）。
