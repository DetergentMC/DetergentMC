# Bedrock プレイテスト手順書（1.7.1〜26.52 クライアント）

Bedrock（統合版）クライアントで DetergentMC に参加する手順と、
結果の記録欄。**本物の Bedrock クライアントでの確認はまだ未実施。**
この文書の項目はすべて未実施のままである。

## 対象

- サーバー：DetergentMC（`minecraft-version` で 1.20.1／1.20.2／
  1.20.4／1.20.5 のどれかを選ぶ。内部 763／764／765／766）
  ＋ Bedrock リスナー（UDP 19132、既定で有効）
- クライアント：Minecraft Bedrock **1.7.1〜26.52**
  （プロトコル 291〜2193 の RakNet 世代。63 プロトコル）。
  サーバーリストには 630／1.20.50 の表示で出る（MOTD は 1 通りしか
  書けないため）。参加時はクライアントのプロトコルに合わせた形式で
  送る。26.60／26.62／26.63／26.65（プロトコル 2225、NetherNet 世代）は
  パケット形式のみ対応済みで、NetherNet リスナーが未実装のため
  参加できない（RakNet 経由で来た場合はその旨の切断メッセージが返る）。
- 対応するもの（プロトコルレベルで検証済み、偽クライアント＋本物のバニラ）：
  サーバーリストへの表示、ログイン、スポーン、チャット（双方向）、移動、
  切断、**スポーン周辺のチャンク（地形が見える）・移動時の新しいチャンクの
  読み込み・ブロック更新の反映**、**他プレイヤー・モブ・落ちたアイテム・
  経験値オーブの表示と移動・消滅、名前と体力の表示、攻撃・インタラクト・
  しゃがみ・ダッシュの操作**。インベントリは送られないため、
  アイテムの使用・インベントリ操作はできない。世界とエンティティが
  見えるのが今回の想定である。虚空しか見えない場合はチャンクが
  届いていない不具合を疑うこと。

## 0. 注意（テスト前に読むこと）

- **Xbox 署名検証は未実装**のため、見知らぬ人に開いたサーバーでは
  テストしないこと。身内のサーバーかローカル環境で行うこと。
  くわしくは `docs/BEDROCK.md` の「セキュリティ」を参照。
- **暗号化なし**（平文）のため、公共 Wi-Fi などではテストしないこと。
- Bedrock クライアントとサーバーは同じ LAN か、ポート 19132/UDP が
  届く環境に置くこと。19132/UDP の開放が必要な場合がある。

## 1. 起動

1. `run/detergentmc.yml` で次を確認する（既定のままでよい）。
   ```yaml
   minecraft-version: "1.20.4"
   server:
     port: 25565
     online-mode: true
   bedrock:
     enabled: true
     port: 19132
     motd: ""
     chunk-radius: 6
   floodgate:
     prefix: "."
   ```
2. `java -jar detergentmc.jar`（または `./gradlew :detergentmc-core:runServer`）で起動する。
3. ログに次が出ること。
   - `Internal server protocol: 765 (Minecraft 1.20.4)`（`minecraft-version` による）
   - `Bedrock リスナーを開始しました（UDP 19132、対象 Bedrock 1.18.33〜26.52 / プロトコル 503〜2193（RakNet））`
   - バニラの `Done (...)!`（ワールド読み込み完了）
4. Java クライアント（1.20.4）で 25565 に参加できることを先に確認する
   （Java 側が動いていることの切り分け用）。

## 2. 参加

1. Bedrock クライアントで「プレイ」→「サーバー」→「サーバーを追加」。
   - 名前：任意（例：DetergentMC）
   - アドレス：サーバーの IP（ローカルならサーバーの LAN IP）
   - ポート：19132
2. サーバーリストに DetergentMC が出ること。MOTD に
   `DetergentMC 1.20.4` と表示されること。出ない場合は
   Unconnected Ping/Pong が届いていない（ファイアウォール／ポート開放を確認）。
3. サーバーを選んで参加する。

## 5. 実機でしか確認できない項目（特に注意）

- Start Game が正しく読めるかどうか（実機で切断される場合は、まず
  Start Game の末尾フィールドと Itemstates の空さを疑うこと）。
  **今回は StartGame に正規パレット（約 2MB・分割フレーム送信）が
  新しく入ったため、ここで切断される可能性が最も高い。切断された場合は
  サーバーログに Start Game 送信の記録があるか確認すること。**
  StartGame の形式は Bedrock バージョンごとに違う（1.20.80 以降の
  hardcore、1.21.0 以降の識別子、1.26.0 以降の末尾の識別子など）。
  切断されたら、どの Bedrock バージョンで・どこまで進んだか（Play
  Status までか、Start Game で止まったか）を記録すること。
- 1.20.50 の正規パレットを全バージョンで送っているため、1.21 以降・
  26.x 系のクライアントでブロックの表示がずれる・切断される
  可能性がある。古いクライアント（1.20.0）と新しいクライアント
  （1.26.50）の両方で、同じ場所のブロック表示を比べて記録すること。
- 1.26 系のアイテム ID は PMMP と minecraft-data で食い違うため、
  1.26.50 クライアントでダイヤの剣・盾などが正しく見えるかどうかを
  特に記録すること（`docs/BEDROCK.md` のアイテム節参照）。
- LevelChunk の表示：地形が崩れて見える・ブロックが石ばかりに見える・
  チャンクが読み込まれない場合は、ランタイム ID 表とサブチャンク
  バージョン 9 の実装を疑うこと（詳細は `docs/BEDROCK.md` のチャンク節）。
- RakNet のアドレス符号化（ビット反転）が実機で正しいかどうか
  （Connection Request Accepted のアドレス部分）。
- 1.20.50 と 1.20.40 での挙動の違い。**今回は 1.7.1〜26.52 の
  63 プロトコルに対応したため、1.7.1・1.8.1・1.9.0・1.10.1・1.11.4・1.12.1・1.13.3・1.14.41・1.14.60・1.16.10・1.16.61・1.16.101・1.16.201・1.16.210・1.16.221・1.17.2・1.17.11・1.17.34・1.17.41・1.18.2・1.18.12・1.18.33・1.19.2・1.19.11・1.19.20・1.19.22・1.19.31・1.19.41・1.19.51・1.19.62・1.19.70・1.19.83・1.20.0・1.20.80・1.21.0・1.26.50
  でも同じ項目を回すこと。**
- モバイル・クライアントでの Itemstates 空によるクラッシュの有無。
- エンティティの表示：他プレイヤー・モブが実機で正しい見た目・
  大きさ・色で出るかどうか。代替で出した種別（例：ブリーズ→
  ブレイズ、テキストディスプレイ→防具立て）が違和感なく見えるか。
  AddEntity の属性（体力）が実機でどう扱われるか。絵画の題名・向きが
  合っているか。落下ブロックの見え方。アイテムフレームが空に見える
  ことは想定どおり（中身は送れない）。
